#### ***\*Thinking 2.2\****

- **\*请从可重用性的角度，阐述用宏来实现链表的好处。\***
- **请你查看实验环境中的 /usr/include/sys/queue.h，了解其中单向链表与循环链表的实现，比较它们与本实验中使用的双向链表，分析三者在插入与删除操作上的性能差异。**

​ 答：（1）使用宏实现链表进行封装，可以实现很强的重复使用，大大减少代码量，例如LIST_NEXT实现之后可以反复使用，在遍历一个链表时常用。LIST_INSERT_HEAD在管理页表时会进行反复的插入，LIST_REMOVE会在从链表中删除某个元素，也十分常用。使用宏来实现链表的功能，一个是可以大大减小代码量，另外是可以让程序更加简洁，增加程序的可读性。

​ （2）

​ 设链表长度为 $n$。

​ 插入头部：三种链表都可以直接找到头部，性能差不多，双向链表和循环链表在插入到头部时修改的指针稍微多一些。时间复杂度均为 $O(n)$

​ 插入尾部：循环链表能够通过头部的前向指针迅速定位到链表尾部，时间复杂度为 $O(1)$.而我们实验的双向链表和环境的单向链表则需要不断遍历到链表的尾部，再将新链表项插到链表尾部,时间复杂度为 $O(n)$。

​ 向前插入：实验的双向链表能够找到前一个链表项的后向指针，环境的循环链表都可以通过插入位置链表项的前向指针找到前一个链表项，所以双向链表和循环链表都能在 $O(1)$向前插入，而单项链表则需要从链表头不断遍历到插入位置的前一个链表项，时间复杂度为 $O(n)$。

​ 向后插入：三种链表都能找到后向指针或者下一个链表项，所以都能在 $O(1)$的时间复杂度内实现向后插入 。其中单项链表的修改的指针少一些，更加简单些。双向链表和循环链表需要保证正确的修改指针顺序，较容易出错。

​ 删除特定元素：由于双向链表和循环链表能找到前一项的后向指针或者前一项链表项，所以能够直接修改前一个链表项的内容，所以能够在 $O(1)$时间复杂度内实现。单项链表则需要从头遍历找到前一项，所以时间复杂度为 $O(n)$。

三种链表不同操作时间复杂度对比如下表, (设链表长度为n)

| | 双向链表 | 单项链表 | 循环链表 |
| --- | --- | --- | --- |
| 插入头部 | O(1) | O(1) | O(1) |
| 插入尾部 | O(n) | O(n) | O(1) |
| 向前插入 | O(1) | O(n) | O(1) |
| 向后插入 | O(1) | O(1) | O(1) |
| 删除特定元素 | O(1) | O(n) | O(1) |

##### ***Thinking2.4***

**请你寻找上述两个 boot_\* 函数在何处被调用。**

答（1）

```C
static Pte *boot_pgdir_walk(Pde *pgdir, u_long va, int create)
```

函数`boot_pgdir_walk`作用是返回一级页表基地址 $\mathrm{pgdir}$对应的两级页表结构中`va` 这一个虚拟地址所在的二级页表项。 如果`create`不为0且对应的二级页表不存在则会使用`alloc`函数分配一页物理内存用于存放。这个函数在`boot_map_segment`函数中被调用，`boot_map_segment`函数对于`size`大小虚拟地址区间内的每一个虚拟地址均调用一次`boot_pgdir_walk`函数，从而实现了将虚拟地址映射到物理地址的区间地址映射。

（2）

```C
void boot_map_segment(Pde *pgdir, u_long va, u_long size, u_long pa, int perm)
```

`boot_map_segment`函数作用是将一级页表基地址`pgdir`对应的两级页表结构做区间地址映射，将虚拟地址区间[va, va+size-1]映射到物理地址区间[pa, pa+size-1]。该函数在`mips_vm_init`中被调用，`mips_vm_init`函数为全局数组`pages`分配npage个页面物理内存用于管理物理内存，然后利用`boot_map_segment`函数将虚拟地址与之间分配的物理页框做映射。此外还需要为全局数组`envs`分配合适大小物理内存用于进程管理，同样需要`boot_map_segment`函数实现虚拟地址与物理地址之间的映射。

###### 在现代的 64 位系统中，提供了 64 位的字长，但实际上不是 64 位页式存储系统。假设在 64 位系统中采用三级页表机制，页面大小 4KB。由于 64 位系统中字长为 8B，且页目录也占用一页，因此页目录中有 512 个页目录项，因此每级页表都需要 9 位。因此在 64 位系统下，总共需要 3 × 9 + 12 = 39 位就可以实现三级页表机制，并不需要 64 位。现考虑上述 39 位的三级页式存储系统，虚拟地址空间为 512 GB，若记三级页表的基地址为 PTbase ，请你计算

- **三级页表页目录的基地址**
- **映射到页目录自身的页目录项(自映射)**

答：

（1）在64位系统中，页面大小为4KB，所以三级页表基地址第`PTBASE>>12`个 页表项，而64位系统中字长位8B，所以二级页表基地址相对于三级页表基地址的偏移位`(PTBASE>>12)<<3=PTBASE>>9`，二级页表基地址为`PTBASE+PTBASE>>9`,页目录相对于二级页表基地址偏移为`(PTBASE>>9>>12)<<3=PTBASE>>18`,所以三级页表结构中页目录的基地址为`PTBASE+PTBASE>>9+PTBASE>>18` .

(2) 映射到页目录自身的页目录地址相对于页目录基地址偏移为`PTBASE>>18>>12<<3=PTBASE>>27`,座椅映射到页目录自身的页目录项地址为`PTBASE+PTBASE>>9+PTBASE>>18+PTBASE>>27`。

##### Thinking2.8

- **简单了解并叙述 X86 体系结构中的内存管理机制，比较 X86 和 MIPS 在内存管理上的区别。**

答：MIPS内存管理使用MMU进行虚拟地址到物理地址的地址映射，主要硬件是TLB，给出虚拟地址想要得到物理地址的话，需要将虚拟地址通过MMU的分页机制映射到物理地址。如果有多个进程对应统一个虚拟地址，还会给每个进程分配不同的物理地址空间。

​ X86架构的内存管理机制分为分段式和分页式两个部分。分段机制能够将程序提供彼此相互分离的代码段、数据段、栈空间等，因此能够避免同一个CPU上运行的多个程序之间互相影响。分页机制实现了按需分页和虚拟内存机制。可以将程序的执行环境按照程序的需求映射到物理内存中，分页机制还可以提供多任务的隔离。X86体系结构，CPU无论在什么状态下都不可以禁止分段机制，但是分页机制是可用可不用的。

​ 分段机制：当程序使用逻辑地址访问内存中的某个部分时候，CPU通过逻辑地址中的段选择符索引段描述表，从而得到这块逻辑内存对应的段描述符。再根据段描述符中的段属性信息检测程序的访问是否合法，如果合法，根据段描述符中的基地址将逻辑地址转换为线形地址
