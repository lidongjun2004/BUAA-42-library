## 一、判断题（正确的打 √，错误的打 ×，每题 2 分，共 20 分）

### 1. 同一进程中的不同线程间可以通过传递指向其栈上对象的指针来相互共享数据

#### 题目

1. 【　　】同一进程中的不同线程间可以通过传递指向其栈上对象的指针来相互共享数据。

#### 答案

**答案：** √（正确）。

同一进程内的线程共享同一个虚拟地址空间，因此一个线程只要拿到另一个线程栈上对象的地址（指针），就可以直接访问该对象。线程的栈是各自独立的，但都位于同一地址空间内，可以互相访问。

### 2. 用户级线程不能修改自己的页表项

#### 题目

2\. 【　　】用户级线程不能修改自己的页表项。

#### 答案

**答案：** √（正确）。

页表由内核建立和维护，修改页表项需要特权指令，只能在内核态完成。用户级线程完全在用户态运行，无法执行修改页表的操作。

### 3. 当进程被 fork 创建后，父进程和子进程中的同一变量将具有相同的虚拟内存地址，但物理内存地址是不相同的

#### 题目

3\. 【　　】当进程被 fork 创建后，父进程和子进程中的同一变量将具有相同的虚拟内存地址，但物理内存地址是不相同的。

#### 答案

**答案：** ×（错误）。

fork 之后父子进程起初共享同一批物理页（写时复制 COW），只有当某一方执行写操作时才会复制出独立的物理页。因此"物理内存地址不相同"这一说法不总成立——未发生写时复制时两者指向同一物理页。

### 4. 消除虚拟内存抖动的最佳方法是增加 I/O 和 CPU 计算之间的并行程度，也就是让 CPU 与 I/O 都“忙”起来，所以增加可运行线程数量可以达到这一目的

#### 题目

4\. 【　　】消除虚拟内存抖动的最佳方法是增加 I/O 和 CPU 计算之间的并行程度，也就是让 CPU 与 I/O 都“忙”起来，所以增加可运行线程数量可以达到这一目的。

#### 答案

**答案：** ×（错误）。

抖动（thrashing）的根源是进程数过多、每个进程分到的物理页框太少，导致频繁缺页。增加可运行线程数量只会让每个进程分到的页框更少、抖动更严重。正确的做法是降低多道程度（减少并发进程数）或增加物理内存，也可采用工作集模型等负载控制手段。

### 5. 大多数 PC 机上的操作系统支持多任务，但不支持多用户

#### 题目

5\. 【　　】大多数 PC 机上的操作系统支持多任务，但不支持多用户。

#### 答案

**答案：** ×（错误）。

主流 PC 操作系统（Windows、Linux、macOS）既支持多任务，也支持多用户。

### 6. 磁盘驱动器上只有一个 MBR（主引导记录），但可能有多个引导扇区

#### 题目

6\. 【　　】磁盘驱动器上只有一个 MBR（主引导记录），但可能有多个引导扇区。

#### 答案

**答案：** √（正确）。

MBR 位于磁盘的 0 号扇区，全盘唯一；而每个分区都可以有自己的分区引导扇区（卷引导记录 VBR），用于引导该分区内的操作系统，因此可能有多个。

### 7. 多个进程可以同时对应到同一个程序/可执行文件

#### 题目

7\. 【　　】多个进程可以同时对应到同一个程序/可执行文件。

#### 答案

**答案：** √（正确）。

同一个可执行文件可以被多次运行，生成多个进程；这些进程的代码段（只读）通常共享同一批物理页，而数据段各自独立。

### 8. 从一个进程到另一个进程的上下文切换无需在内核模式下执行操作系统代码即可完成

#### 题目

8\. 【　　】从一个进程到另一个进程的上下文切换无需在内核模式下执行操作系统代码即可完成。

#### 答案

**答案：** ×（错误）。

上下文切换需要保存/恢复寄存器现场、切换页表（地址空间）、切换内核栈等，这些都只能由内核态的调度程序完成，因此一定需要进入内核模式。

### 9. 动态重定位是指硬件在每次内存访问时动态实现地址的转换

#### 题目

9\. 【　　】动态重定位是指硬件在每次内存访问时动态实现地址的转换。

#### 答案

**答案：** √（正确）。

动态重定位在程序执行期间由硬件（基址/界限寄存器，或页表、段表等地址转换机构）在每次访存时把逻辑地址转换为物理地址；与之相对的静态重定位是在装入时一次性完成地址转换。

### 10. 进程中的线程必须有自己独立的栈

#### 题目

10\. 【　　】进程中的线程必须有自己独立的栈。

#### 答案

**答案：** √（正确）。

线程是 CPU 调度的基本单位，各自拥有独立的程序计数器、寄存器和栈，才能独立被调度和切换；同一进程内的线程共享代码段、数据段和打开的文件等其他资源。

### 1. FIFO 与 LRU 算法下的缺页次数

1. 某进程运行时依次访问的内存页面为：A B D D E F A A C F G D A C G D C E。采用 FIFO 算法进行页面置换，共为该进程分配了 4 个页框，初始时这 4 个页框均为空，则完成上述内存页面访问会产生__________次缺页中断；如果采用 LRU 算法进行页面置换，其他条件不变，则会产生__________次缺页中断。

| 14 | C | A C G D | 命中 |
| 15 | G | A C G D | 命中 |
| 16 | D | A C G D | 命中 |
| 17 | C | A C G D | 命中 |
| 18 | E | C G D E（换出 A） | 缺页 |

LRU（换出最久未使用的页）：

    7    void enter_region( int process )
    8    {

   18

## 四、存储管理（共 15 分）

### 1. 32 位虚拟内存系统的页表项数量（共 8 分）

在一个 32 位虚拟内存系统中，页面大小为 4KB。

#### （1）页表被全部占用时，1 级页表与 20 级页表各需要多少页表项（4 分）

**答案：**

- 采用 1 级页表： $2^{20}=$ **1M 个页表项**
- 采用 20 级页表：每级页表在虚拟地址中仅占 1 位，能够区分 2 个页表项。页表项全部被占用，则相当于构建一个满二叉树。所以所有页表项数量为

$$
2+4+\cdots+2^{20}=2\left(2^{20}-1\right)
$$

即约 **2M 个页表项**。如果考虑自映射，2M 页表项中有一半是重复的，因此答 1M 页也算对。

#### （2）进程只分配 1 页内存时，1 级页表与 20 级页表各需分配多少页表项（4 分）

**答案：** 如果进程只占用 1 页内存：

- 对于 1 级页表仍要分配 **1M 个页表项**（并且要连续存储空间）
- 对于 20 级页表来说，仅需要 20 个级别每一级分配 1 个页表（2 个页表项），总共需要 **40 个页表项**

## 五、页表自映射（5 分）

一个 32 位的虚拟存储系统有两级页表，逻辑地址第 22 到 31 位是第一级页表索引，12 到 21 位是第二级页表索引，页内偏移占 0 到 11 位；进程地址空间 4GB，从 0x8C000000 开始映射 4MB 的页表。

### （1）给出一级页表的起始虚拟地址（2 分）

**答案：** **0x8C230000**

4MB 页表共 $2^{22}/2^{12}=2^{10}=1024$ 页，映射范围是 0x8C000000 ~ 0x8C3FFFFF，该范围内逻辑地址的一级页表索引恒为

$$
0x8C000000 \gg 22 = 0x230
$$

自映射要求一级页表自身逻辑地址中的一级索引字段等于它所在的物理页框号，故一级页表的页框号为 0x230。页表区从页框 0 开始连续存放，页框 0x230 即页表区的第 0x230 页，其虚拟地址为

$$
0x8C000000+0x230\times 4096=0x8C000000+0x230000=0x8C230000
$$

### （2）给出一级页表中映射自己的表项的虚拟地址（3 分）

**答案：** **0x8C2308C0**

映射自己的表项就是一级页表中存放"页框号 0x230"的那一项，即一级页表的第 0x230 项。每项 4 字节，故其地址为

$$
0x8C230000+0x230\times 4=0x8C230000+0x8C0=0x8C2308C0
$$

## 六、进程与线程（共 10 分）

### 题目

假设进程只有三种基本状态，画出进程的状态转换图，并举例说明这些转换发生的条件。

### 答案

**答案：** 三种基本状态为就绪（Ready）、运行（Running）、阻塞（Blocked），状态转换关系如下：

| 转换 | 发生条件 |
| --- | --- |
| 就绪 → 运行 | 时间一到，调度程序选择一个进程运行 |
| 运行 → 就绪 | 运行进程用完了时间片；运行进程被中断，因为一高优先级进程处于就绪状态 |
| 运行 → 阻塞 | 当一进程所需的东西必须等待时；OS 尚未完成服务；对一资源的访问尚不能进行；初始化 I/O 且必须等待结果；等待某一进程提供输入（IPC） |
| 阻塞 → 就绪 | 当所等待的事件发生时 |

状态转换图可表示为：就绪 —（调度）→ 运行；运行 —（时间片用完 / 被高优先级进程抢占）→ 就绪；运行 —（请求 I/O、等待资源或事件）→ 阻塞；阻塞 —（等待的事件完成）→ 就绪。注意阻塞态不能直接转为运行态，必须先回到就绪态。

## 七、进程管理：信号量基础（10 分）

### （1）调用一次 P(s) 和 V(s) 操作后 s.count 和 s.queue 的变化（4 分）

**答案：**

1. 调用 P(s)，s.count 会减 1，如果 s.count < 0，则阻塞调用 P(s) 的进程，并将其放入 s.queue；
2. 调用 V(s)，s.count 会加 1，如果 s.count ≤ 0，则从 s.queue 中取出一个进程，将其置为就绪。

### （2）用 test-and-set 指令实现 P(s) 和 V(s) 操作（6 分）

**答案：**

```c
// 1) P(s)
while (test-and-set(lock) == 1) ;
s.count--;
if (s.count < 0) {
    block 进程;
    将进程放到 s.queue;
}
*lock = 0;

// 2) V(s)
while (test-and-set(lock) == 1) ;
s.count++;
if (s.count <= 0) {
    从 s.queue 中取出一个进程，置为就绪态;
}
*lock = 0;
```

`while (test-and-set(lock) == 1) ;` 是自旋等待获取互斥锁，保证对 `s.count` 与 `s.queue` 的修改是互斥的（临界区）；临界区执行完后用 `*lock = 0` 释放锁。需要注意：如果进程在 P(s) 中被阻塞，必须先释放 `lock` 再进入阻塞，否则其他进程无法进入 V(s) 唤醒它，会造成死锁——上面伪代码中"将进程放到 s.queue"之后、`*lock = 0` 之前若真正进入阻塞状态，就存在这一风险，实际实现中通常先把进程挂入队列并置为阻塞态（并不真正让出 CPU），出临界区后再由调度程序完成切换。
