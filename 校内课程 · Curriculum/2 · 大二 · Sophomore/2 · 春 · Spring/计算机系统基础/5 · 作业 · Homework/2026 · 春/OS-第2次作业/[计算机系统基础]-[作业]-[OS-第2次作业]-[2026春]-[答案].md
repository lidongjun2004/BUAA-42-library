# 计算机系统基础 OS-第2次作业答案（2026春）

## 1

### 题目

在一个交换系统中，按内存地址排列的空闲区大小是：10KB、4KB、20KB、18KB、7KB、9KB、12KB 和 15KB。对于连续的段请求：12KB、10KB、9KB。使用 FirstFit、BestFit、WorstFit 和 NextFit 将找出哪些空闲区？

### 答案

**答案：**

1. FirstFit：从链首开始找第一个足够大的空闲区。
   - 12KB -> 20KB（剩余 8KB），空闲区变为 10，4，8，18，7，9，12，15
   - 10KB -> 10KB（剩余 0KB），空闲区变为 4，8，18，7，9，12，15
   - 9KB -> 18KB（剩余 9KB），空闲区变为 4，8，9，7，9，12，15
2. BestFit：选择满足要求且最小的空闲区。（将空闲分区链中的空闲分区按照空闲分区由小到大的顺序排序，从而形成空闲分区链。每次从链首进行查找合适的空闲分区为作业分配内存，这样每次找到的空闲分区是和作业大小最接近的，所谓“最佳”。）
   - 12KB -> 12KB（剩余 0KB），空闲区变为 10，4，20，18，7，9，15
   - 10KB -> 10KB（剩余 0KB）
   - 9KB -> 9KB（剩余 0KB）
3. WorstFit：选择最大的空闲区。（与最佳适应算法刚好相反，将空闲分区链的分区按照从大到小的顺序排序形成空闲分区链，每次查找时只要看第一个空闲分区是否满足即可。）
   - 12KB -> 20KB（剩余 8KB）
   - 10KB -> 18KB（剩余 8KB）
   - 9KB -> 15KB（剩余 6KB）
4. NextFit：从上次分配位置开始循环查找下一个足够大的空闲区。通常维护一个指针。
   - 12KB -> 20KB（剩余 8KB），空闲区变为 10，4，8，18，7，9，12，15
   - 10KB -> 18KB（剩余 8KB），空闲区变为 10，4，8，8，7，9，12，15
   - 9KB -> 9KB（剩余 0KB）

### 2

#### 题目

解释逻辑地址、物理地址、地址映射，并举例说明。

#### 答案

**答案：**

逻辑地址（虚拟地址）：由 CPU 生成的地址，是用户程序看到的地址空间中的地址。

物理地址：内存中实际的地址。

地址映射：将逻辑地址转换为物理地址的过程，通常由内存管理单元（MMU）完成。

举例：假设一个逻辑地址为 0x1234，基地址为 0x1000，则物理地址为 0x1000 + 0x1234 = 0x2234。

### 3

#### 题目

解释页式（段式）存储管理中为什么要设置页（段）表和快表，简述页式（段式）地址转换过程。

#### 答案

**答案：**

页表：用于页式存储管理，保存逻辑页到物理页的映射。

快表（TLB）：缓存页表项以加快地址转换。

转换过程：

1. CPU 给出逻辑地址（页号 p，偏移 d）；
2. 以页号 p 查找 TLB；若命中，直接获得物理页框号 f；
3. 若 TLB 未命中，通过页表基址寄存器找到主存中的页表，以 p 为索引读取页表项，获得 f，并将该页表项装入 TLB；
4. 若页表项中有效位为 0，引发缺页中断，由操作系统调页；
5. 物理地址 = $f \times$ 页面大小 $+ d$。

### 4

#### 题目

叙述缺页中断的处理流程。

#### 答案

**答案：**

1. CPU 检测到缺页中断。
2. 保存当前 CPU 状态。
3. 调用缺页中断处理程序。
4. 检查请求的页面是否存在于外存中。
5. 若存在，则调入内存并更新页表。
6. 若不存在，则产生错误。
7. 恢复 CPU 状态，重新执行引起缺页中断的指令。

### 5

#### 题目

假设一个机器有 38 位的虚拟地址和 32 位的物理地址。

1. 与一级页表相比，多级页表的主要优点是什么？
2. 如果使用二级页表，页面大小为 16KB，每个页表项有 4 个字节。应该为虚拟地址中的第一级和第二级页表域各分配多少位？

#### 答案

**答案：**

（1）多级页表的优点：

- 内存节省：多级页表使用时只需要在内存中存储实际使用的页表部分，而一级页表则需要在内存中存储完整的页表。对于大的虚拟地址空间，这可以节省大量的内存。
- 提高查找效率：多级页表将页表分为多级，每一级只需要存储部分地址空间的信息，这样可以减少每一级页表的大小，从而提高查找效率。
- 减少碎片：多级页表可以按需分配内存，避免了一级页表中需要为每个进程分配大量连续虚拟地址空间的问题，减少了内存碎片。

（2）页面大小 16KB = $2^{14}$B，页内偏移需 14 位。页表项 4B = $2^2$B，因此一个页面可容纳 $2^{14}/2^2=2^{12}$ 个页表项，每级索引域需 12 位。虚拟地址共 38 位，剩余 $38-14=24$ 位用于两级页表，则第一级页表域 12 位，第二级页表域 12 位。

虚拟地址的结构如下：

[ 第一级页表索引 (12 bits) | 第二级页表索引 (12 bits) | 页面偏移 (14 bits) ]

### 6

#### 题目

假设页面的访问存在一定的周期性循环，但周期之间会随机出现一些页面的访问。例如：0,1,2…,511,431,0,1,2…511,332,0,1,2,…,511 等。请思考：

1. LRU、FIFO 和 Clock 算法的效果如何？
2. 如果有 500 个页框，能否设计一个优于 LRU、FIFO 和 Clock 的算法？

#### 答案

**答案：**

（1）

1. LRU（Least Recently Used）算法：LRU 算法根据最近未被使用的时间来淘汰页面。对于周期性访问的情况，LRU 能较好地识别并保持最近使用的页面。然而，当出现随机访问的页面（如 431、332 等），这些页面会暂时占用一个页框，然后很快被新的周期性访问页面所替换。总体而言，LRU 在处理这种访问模式时表现最好。
2. FIFO（First In First Out）算法：FIFO 算法简单地根据页面进入内存的顺序来淘汰最早进入的页面。对于周期性访问的情况，FIFO 会不断淘汰最早的页面。当出现随机访问时，这些随机页面会暂时占用一个页框，导致周期性页面被替换。FIFO 在这种情况下可能会频繁发生缺页，表现相对较差。
3. Clock 算法：Clock 算法是 FIFO 的改进版本，增加了一个“使用位”来判断页面是否被使用。Clock 算法在处理周期性访问时，比 FIFO 稍好，因为它可以通过使用位跳过一些最近访问的页面。然而，当随机访问页面时，Clock 算法也会遇到类似的问题，即这些页面会占用页框，影响周期性页面的保持，表现优于 FIFO，弱于 LRU。

（2）由于有 500 个页框，而周期性访问的页面数量是 512 个，加上一些随机访问的页面，可以设计一个针对这种特定模式的混合算法：

增强的周期性访问识别算法：

1. 固定页框分配：将大部分页框（例如 480 个）分配给周期性访问的页面。这样，即使随机访问页面进入内存，也不会影响周期性访问页面的存储。
2. 随机访问页面缓冲区：将剩余的页框（例如 20 个）专门用于处理随机访问页面。使用 LRU 算法管理这部分页框，因为随机访问页面不一定会重复访问，LRU 能较好地处理这类页面。
3. 周期识别机制：实现一个机制来识别周期性访问的页面序列，并对这些页面进行专门的管理，确保周期性页面尽量保持在内存中。
4. 动态调整：实时监测页面访问模式，动态调整页框分配比例。例如，若随机访问频率增加，可以适当增加随机访问缓冲区的页框数量。

### 7

#### 题目

伙伴系统（Buddy System）是一种非常经典的物理内存管理机制。请简述在伙伴系统中释放一块内存时，系统是如何进行空闲块合并的？合并时，必须满足哪几个条件才能称这两个内存块为“伙伴”？

#### 答案

**答案：**

- 释放内存块时，系统会检查该块的伙伴是否也为空闲。若伙伴空闲，则将两块合并为一个更大的块，并递归向上检查合并后的新块是否又能与它的伙伴合并，直至无法合并或达到最大块为止。
- 两个内存块互为“伙伴”必须满足的三个条件：
  1. 大小相同：两块具有相同的尺寸（均为 $2^k$ 大小）；
  2. 地址相邻：两块在物理内存中地址连续；
  3. 同源分裂：低地址块的起始地址按两倍块大小对齐（即它们是从同一个更大的块中一分为二得到的）。

### 8

#### 题目

假设某系统采用二级页表，内存的单次物理访问时间为 100ns。TLB 的访问时间为 10ns，TLB 命中率为 95%。此外，系统配有 L1 Cache，Cache 的访问时间为 5ns，命中率为 98%。假设页表项和实际数据都可以被缓存在 L1 Cache 中。

1. 在最佳情况（TLB 命中且数据在 Cache 中命中）下，CPU 获取到目标数据需要多长时间？
2. 计算该系统在运行中获取目标数据的平均内存访问时间（Effective Access Time, EAT）

#### 答案

**答案：**

设 TLB 访问时间 = 10ns，命中率 = 95%；L1 Cache 访问时间 = 5ns，命中率 = 98%；物理内存访问时间 = 100ns；页表项和数据均可缓存。

（1）最佳情况（TLB 命中且数据在 Cache 命中）：

访问时间 = TLB 访问时间 + Cache 访问时间 = 10ns + 5ns = 15ns。

（2）平均内存访问时间（EAT）计算（串行模型，TLB 查找本身无论是否命中均消耗 10ns）：

数据访问平均时间 = Cache 时间 + Cache 未命中率 $\times$ 内存时间 = $5 + (1-0.98)\times100 = 7$ns。

页表访问平均时间 = $5 + (1-0.98)\times100 = 7$ns。

TLB 命中时的平均时间 = 10（TLB）+ 7（数据访问）= 17ns。

TLB 未命中时的平均时间 = 10（TLB）+ 7（页表访问）+ 7（数据访问）= 24ns。

EAT = $0.95\times17 + 0.05\times24 = 16.15 + 1.2 = 17.35$ns。
