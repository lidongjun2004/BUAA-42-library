## 1

### 题目

读者写者问题（写者优先）：1）共享读；2）互斥写、读写互斥；3）写者优先于读者（一旦有写者，则后续读者必须等待，唤醒时优先考虑写者）。

### 答案

**答案：**

- 共享读：多个读者可同时访问资源。
- 互斥写、读写互斥：写者必须独占资源，读者和写者不能同时访问。
- 写者优先：一旦有写者到达，后续读者必须等待；唤醒时优先唤醒写者。
- 需要信号量：
  - `resource`：表示读写互斥（写者独占，第一个读者占用，最后一个读者释放）。
  - `readtry`：写者优先的关键，写者到达时阻止新读者进入。
  - `rmutex`、`wmutex`：分别保护读者计数和写者计数。
- 步骤：
  1. 读者到达时，先尝试进入 `readtry`（如果写者排队，则读者被阻塞）。
  2. 第一个读者获取 `resource`，阻止写者。
  3. 读者计数增加，释放 `readtry`（让后续读者继续）。
  4. 读完后，最后一个读者释放 `resource`。
  5. 写者到达时，增加写者计数；第一个写者获取 `readtry`，阻止新读者。
  6. 写者获取 `resource`（等待当前读者/写者离开），写完后释放。
  7. 最后一个写者释放 `readtry`，允许读者进入。

伪代码

```c
sem_t rmutex, wmutex, readtry, resource;
int readcount = 0, writecount = 0;

void reader() {
    sem_wait(&readtry);
    sem_wait(&rmutex);
    if (++readcount == 1) sem_wait(&resource);
    sem_post(&rmutex);
    sem_post(&readtry);

    // 读操作

    sem_wait(&rmutex);
    if (--readcount == 0) sem_post(&resource);
    sem_post(&rmutex);
}

void writer() {
    sem_wait(&wmutex);
    if (++writecount == 1) sem_wait(&readtry);
    sem_post(&wmutex);

    sem_wait(&resource);
    // 写操作
    sem_post(&resource);

    sem_wait(&wmutex);
    if (--writecount == 0) sem_post(&readtry);
    sem_post(&wmutex);
}
```

### 2

#### 题目

寿司店问题。假设一个寿司店有 5 个座位，如果你到达的时候有一个空座位，你可以立刻就坐。但是如果你到达的时候 5 个座位都是满的有人已经就坐，这就意味着这些人都是一起来吃饭的，那么你需要等待所有的人一起离开才能就坐。编写同步原语，实现这个场景的约束。

#### 答案

**答案：**

- 店内有 5 个座位。如果座位有空，顾客直接就坐。
- 如果座位满，说明这些人在等一个团体离开；后来的顾客必须等待所有当前顾客离开后才能一起进入。
- 用 `count` 表示当前店内人数，`waiting` 表示等待队列人数，`enter` 信号量让等待者阻塞。
- 步骤：
  1. 顾客到达，互斥检查座位。
  2. 若 `count < 5`，直接就坐，`count++`。
  3. 否则 `waiting++`，然后在 `enter` 上等待。
  4. 就餐结束后，互斥更新 `count--`。
  5. 如果 `count == 0` 且有等待者，说明这批团体已全部离开，唤醒所有等待者（即让他们一起进入），并重置 `waiting`。

代码块

```c
sem_t mutex, enter;
int count = 0, waiting = 0;

void customer() {
    sem_wait(&mutex);
    if (count < 5) {
        count++;
        sem_post(&mutex);
    } else {
        waiting++;
        sem_post(&mutex);
        sem_wait(&enter);
    }

    // 就餐

    sem_wait(&mutex);
    count--;
    if (count == 0 && waiting > 0) {
        while (waiting--) sem_post(&enter);
    }
    sem_post(&mutex);
}
```

### 3

#### 题目

进门问题。

1. 请给出 P、V 操作和信号量的物理意义。
2. 一个软件公司有 5 名员工，每人刷卡上班。员工刷卡后需要等待，直到所有员工都刷卡后才能进入公司。为了避免拥挤，公司要求员工一个一个通过大门。所有员工都进入后，最后进入的员工负责关门。请用 P、V 操作实现员工之间的同步关系。

#### 答案

**答案：**

P、V 操作和信号量的物理意义

- 信号量：是一个整型变量，代表某种资源的可用数量或等待进程的计数。信号量的值只能通过 P、V 操作原子地改变。
  物理意义：例如信号量 `S` 表示当前可用的资源数（`S > 0`），若 `S < 0` 则其绝对值表示等待该资源的进程数。
- P 操作（Proberen，测试）：
  `P(S)` 的物理意义是申请一个资源。
  执行过程：`S = S - 1`；如果 `S < 0`，则当前进程进入阻塞队列（等待资源）；否则继续执行。
  相当于：如果资源可用，则占用一个；否则排队等待。
- V 操作（Verhogen，增加）：
  `V(S)` 的物理意义是释放一个资源。
  执行过程：`S = S + 1`；如果 `S <= 0`，则唤醒一个在该信号量上等待的进程。
  相当于：归还一个资源，并通知可能正在等待的进程。

实现步骤：

- 5 名员工，必须全部刷卡后才能开始进门。
- 进门时一个一个通过（互斥）。
- 最后进入的员工负责关门。
- 需要：
  - `mutex` 保护刷卡计数。
  - `all_card` 信号量：让前 4 人等待最后一人刷卡完成。
  - `door` 信号量：控制一次一人通过。
  - 计数器 `card_count`，以及 `remain` 记录尚未通过的人数。
- 步骤：
  1. 刷卡阶段：
     - 每个员工进入刷卡区，互斥修改 `card_cnt`。
     - 如果不是最后一个刷卡者（`card_cnt < 5`），则执行 `P(all_card)` 阻塞自己，等待最后一人。
     - 如果是最后一个刷卡者，则连续执行 `V(all_card)` 4 次，唤醒所有等待的员工。
  2. 进门阶段：
     - 所有被唤醒的员工（包括最后一个刷卡者）依次竞争 `door` 信号量，保证一次只有一人通过。
     - 通过大门后，`remain--`。
     - 若 `remain == 0`（即最后一人通过），则执行关门动作。

代码块

```c
semaphore mutex = 1;
semaphore all_card = 0;
semaphore door = 1;
int card_cnt = 0;
int remain = 5;

void employee() {
    //刷卡
    P(mutex);
    card_cnt++;
    if (card_cnt < 5) {
        V(mutex);
        P(all_card);         // 等待最后一个刷卡者唤醒
    } else {
        // 最后一人，唤醒其他4人
        for (int i = 1; i <= 4; i++)
            V(all_card);
        V(mutex);
    }

    //依次进门
    P(door);                  // 互斥通过大门
    // 通过大门
    remain--;
    if (remain == 0) {
        // 最后进入的人关门
        close_door();
    }
    V(door);
}
```

### 4

#### 题目

搜索-插入-删除问题。三个线程对一个单链表进行并发的访问，分别进行搜索、插入和删除。搜索线程仅仅读取链表，因此多个搜索线程可以并发。插入线程把数据项插入到链表最后的位置；多个插入线程必须互斥防止同时执行插入操作。但是，一个插入线程可以和多个搜索线程并发执行。最后，删除线程可以从链表中任何一个位置删除数据。一次只能有一个删除线程执行；删除线程之间，删除线程和搜索线程，删除线程和插入线程都不能同时执行。请编写三类线程的同步互斥代码，描述这种三路的分类互斥问题。

#### 答案

**答案：**

- 搜索线程：只读，多个可并发。
- 插入线程：写链表尾，互斥于其他插入；但可和搜索并发。
- 删除线程：互斥于所有其他线程（搜索、插入、删除）。
- 信号量：
  - `rw_mutex`：删除与搜索/插入的互斥。
  - `insert_mutex`：插入互斥。
  - `mutex` 保护并发计数（搜索+插入的总并发数）。
- 步骤：
  1. 搜索线程：若没有其他线程（搜索+插入），则占用 `rw_mutex`，然后增加计数。搜索完成后释放。
  2. 插入线程：先竞争 `insert_mutex`（一次一个插入），然后与搜索一样增加计数，占用 `rw_mutex` 仅当没有搜索/插入时。插入完成后释放。
  3. 删除线程：直接 `P(rw_mutex)`，确保与一切互斥，完成后 `V(rw_mutex)`。

代码块

```c
#include <pthread.h>
#include <semaphore.h>

// 信号量定义
sem_t rw_mutex;        // 删除与其他所有操作的互斥锁（删除 vs 搜索+插入）
sem_t insert_mutex; // 插入线程之间的互斥锁
sem_t mutex;        // 保护读者计数 read_count

int read_count = 0;   // 当前正在执行搜索或插入的线程数

// 搜索线程（只读）
void *search(void *arg) {
    // 增加读者计数，如果是第一个则阻止删除
    sem_wait(&mutex);
    if (read_count == 0) {
        sem_wait(&rw_mutex);    // 阻止删除线程
    }
    read_count++;
    sem_post(&mutex);

    // 执行搜索操作（读链表）
    // ...

    // 减少读者计数，如果是最后一个则允许删除
    sem_wait(&mutex);
    read_count--;
    if (read_count == 0) {
        sem_post(&rw_mutex);    // 允许删除线程
    }
    sem_post(&mutex);

    return NULL;
}

// 插入线程（写链表尾部，但与搜索可并发）
void *insert(void *arg) {
    // 插入之间互斥：一次只能有一个插入线程
    sem_wait(&insert_mutex);

    // 增加读者计数，如果是第一个则阻止删除
    sem_wait(&mutex);
    if (read_count == 0) {
        sem_wait(&rw_mutex);
    }
    read_count++;
    sem_post(&mutex);

    // 执行插入操作（写链表尾部）
    // ...

    // 减少读者计数，如果是最后一个则允许删除
    sem_wait(&mutex);
    read_count--;
    if (read_count == 0) {
        sem_post(&rw_mutex);
    }
    sem_post(&mutex);

    // 释放插入互斥锁
    sem_post(&insert_mutex);

    return NULL;
}

// 删除线程（可删除任意位置，与一切互斥）
void *delete(void *arg) {
    // 获得全局互斥锁，阻止所有搜索、插入和其他删除
    sem_wait(&rw_mutex);

    // 执行删除操作
    // ...

    // 释放全局互斥锁
    sem_post(&rw_mutex);

    return NULL;
}

int main() {
    // 初始化信号量
    sem_init(&rw_mutex, 0, 1);
    sem_init(&insert_mutex, 0, 1);
    sem_init(&mutex, 0, 1);

    // 创建线程并运行...
    return 0;
}
```

- 搜索与插入并发：它们共享同一个 `read_count`，都通过 `rw_mutex` 来阻止删除，但彼此之间不互斥（除了插入之间通过 `insert_mutex` 互斥）。
- 删除完全独占：删除线程直接获取 `rw_mutex`，此时任何搜索或插入尝试都会在 `rw_mutex` 上阻塞，且其他删除也无法进入。
- `read_count` 保护：`mutex` 确保对 `read_count` 的修改是原子操作。

#### 题目

公园购票问题。在五一期间，某公园实行限流访问，规定每天最多允许 N 个人购票入园。公园的在线售票系统提供了查询余票和在线购票功能，查询者 Q 和购票者 B 分别对余票数量进行读操作和写操作。为了简化问题，假定每次只能买一张票。请基于 PV 操作设计一个算法，实现多个 Q 和 B 对余票数量的并发访问。要求：(1) Q 和 B 按照到达顺序对余票数量进行访问；(2) 当多个 Q 连续到达时，应允许它们并发读取余票数量；(3) 当余票为 0 时，不允许 B 执行写操作。

#### 答案

**答案：**

- 余票数量为 `tickets`。
- 查询者（Q）可并发读，购票者（B）写操作（每次一张票）。
- 要求：
  - Q 和 B 按到达顺序访问（公平队列）。
  - 多个 Q 连续到达时可并发读。
  - 余票=0 时，B 不能执行写操作。
- 信号量：
  - `queue`：保证到达顺序，一次只有一个进程进入临界区（按顺序访问），但读操作内部可以并发。
  - `write_lock`：写者互斥，且阻止读者在写者前进入。
  - `mutex`：保护读者计数。
- 步骤：
  1. 所有 Q 和 B 先执行 `P(queue)` 排队。
  2. Q：第一个读者 `P(write_lock)`，读者计数++，释放 `queue`。读操作后，最后一个读者 `V(write_lock)`。
  3. B：获得 `queue` 后，再 `P(write_lock)` 阻塞其他读者和写者，检查余票，若 >0 则减 1（购票），最后释放 `write_lock` 和 `queue`。

代码块

```c
sem_t queue, write_lock, mutex;
int readers = 0, tickets = N;

void query() {
    sem_wait(&queue);
    sem_wait(&mutex);
    if (readers++ == 0) sem_wait(&write_lock);
    sem_post(&mutex);
    sem_post(&queue);

    // 读 tickets

    sem_wait(&mutex);
    if (--readers == 0) sem_post(&write_lock);
    sem_post(&mutex);
}

void buyer() {
    sem_wait(&queue);
    sem_wait(&write_lock);

    if (tickets > 0) tickets--;

    sem_post(&write_lock);
    sem_post(&queue);
}
```
