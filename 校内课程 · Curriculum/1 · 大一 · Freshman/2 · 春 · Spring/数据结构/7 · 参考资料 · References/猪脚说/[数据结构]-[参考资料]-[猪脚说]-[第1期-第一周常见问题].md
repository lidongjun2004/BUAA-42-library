## 1. 值传递?

举一个常见的例子:

```c
void swap(int a, int b) {
    int tmp = a;
    a = b;
    b = tmp;
}

int main() {
    int i = 2, j = 4;
    swap(i, j); // i 和 j 交换了吗?
    return 0;
}
```

我们把这一写法代入函数调用处, 看看发生了什么.

```c
int main() {
    int i = 2, j = 4;
    // swap(i, j);
    {
        int a = i, b = j; // 值传递
        // 以下是函数内部的
        int tmp = a;
        a = b;
        b = tmp;
    }
    // i 和 j 交换了吗? 显然不!
    return 0;
}
```

下面的实现才能正确进行变量值交换.

```c
void swap(int *a, int *b) {
    int tmp = *a;
    *a = *b;
    *b = tmp;
}

int main() {
    int i = 2, j = 4;
    swap(&i, &j);
    return 0;
}
```

不信? 你把将这一写法代入函数调用处吧.

```c
int main() {
    int i = 2, j = 4;
    // swap(&i, &j);
    {
        int *a = &i, *b = &j; // 值传递
        // 以下是函数内部的
        int tmp = *a;
        *a = *b;
        *b = tmp;
    }
    return 0;
}
```

**虽然这一"代入"过程并不十分严谨, 但能够基本反映函数参数调用过程中的"值传递". 要想修改外面的值, 就需要传入外面的值的地址(即指针).**

看一个难一些的例子, 我们要用 `add1` 函数, 对 `int*` 型指针 `p` 进行**后移一单位**的操作.

**既然是要修改 `p` 那肯定就需要传入 `p` 的地址**, 即传入的参数类型是 `int**` (`int*` 型指针**的指针**). 先看看写法是怎么样的:

```c
void add1(int **pointer) {
    *pointer = *pointer + 1;
}

int main() {
    int a[] = {1, 2, 3, 4};
    int *p = a;
    add1(&p);
    printf("%d\n", *p); // 2
    return 0;
}
```

困惑吗? 代入调用过程看看:

```c
int main() {
    int a[] = {1, 2, 3, 4};
    int *p = a;
    // add1(&p);
    {
        int **pointer = &p; // int*型取地址当然是int**型的
        *pointer = *pointer + 1; // 不就是 p = p + 1 吗
    }
    printf("%d\n", *p); // 2
    return 0;
}
```

这样看, 你是否明白"值传递"了呢?

有同学说, 这不折腾么? 为什么要把这样简单的功能变成函数呢? 我答, 举这几个简单的例子只是为了深化同学们的理解, 使用函数的目的就是让程序分成几块, **只要保证每一块都正确运行, 块与块间的调用关系正确, 就能够保证大程序的正确!** 如果把所有的逻辑处理都放在一个函数中进行处理, 那就极难进行调试. **有时候我们需要使用函数对调用者所在区域的某个变量进行修改, 就需要用到这部分讲的指针传递.**

> 多使用函数, 使得程序**更容易调试, 更容易迁移, 更容易扩展(更普适)**.

## 2. 谁是真? 谁是假?

C语言中并未把更高级语言的 `true/false` 列入基本数据类型, 而是用 `int` 代替其功能:

1. 用**零**代表`false`(这个我相信你明白);
2. 用**非零**代表`true`(这个我觉得你不太懂)!

也就是说 `2, 4, -1, -3` 都代表 `true` ! 这一点十分重要, 有些同学使用C库函数时往往忘记这一点, 下面是**人类早期驯服C语言真假值的珍贵资料**:

```c
isdigit(character) == 1 // 错! 不应该判 == 1
isalpha(character) == 1 // 同上
```

类似的, `strcmp(s1, s2)` 函数也有类似的设定: `s1` 大于 `s2` 时返回正数, `s1` 小于 `s2` 时返回负数, 两者相等时返回 `0` . 所以做判定时, **应该判大于零, 小于零, 等于零**, 而不是**等于 `1` , 等于 `0` , 等于 `-1`**.

## 3. 遍历字符串? 时间复杂度?

考虑使用循环, 记录**空格字符**在字符串中的数目, 有些同学使用如下的方式遍历字符串:

```c
char str[] = "1  23  34 3 4 3 5 3";
int i;
int cnt = 0;
for (i = 0; i < strlen(str); ++i) {
    if (str[i] == ' ') {
        ++cnt;
    }
}
```

这个循环有一个很大的问题. 回顾 `for` 的执行过程, 容易发现**每循环一次, `i < strlen(str)` 就执行一次**, 这意味着每次循环都调用了一次 `strlen` 函数求字符串长度. 事实上, `strlen` 的本质就是对字符串进行遍历, 看 `'\0'` 前有多少个字符. 因此上面的这个写法相当于是一个**二重循环**!! 也就是说, 若字符串长度为 $n$ , 那么这个算法的时间复杂度就是 $O(n^2)$ . (不划算吧?)

来做一些优化. 由于字符串长度不变, 所以可以提前求出长度, 改写上述循环如下:

```c
char str[] = "1  23  34 3 4 3 5 3";
int i;
int len = strlen(str);
int cnt = 0;
for (i = 0; i < len; ++i) {
    if (str[i] == ' ') {
        ++cnt;
    }
}
```

这样, 时间复杂度降低为 $O(n)$ . 但是我们发现, 这个写法其实会遍历字符串两次(`strlen` 一次, 手写的 `for` 循环一次). 有没有办法只循环一次就完成呢? 当然有的, 写法如下:

```c
char str[] = "1  23  34 3 4 3 5 3";
int i;
int cnt = 0;
for (i = 0; str[i] != '\0'; ++i) {
    if (str[i] == ' ') {
        ++cnt;
    }
}
```

这样, 当遍历到字符串末端的 `'\0'` 时, 循环就退出了. 希望同学们掌握这种写法!

## 4. 常用"缩写"

C语言的赋值语句是有"返回值"的, 举一个简单常见的例子:

```c
int a = b = 0;
```

这事实上是利用了赋值语句的"返回值". 赋值语句首先计算 `=` 右端的值, 然后复制到 `=` 左端的变量中, **同时返回 `=` 右端的值**. 也就是说, 上述语句的实际执行过程是:

1. 要计算 `a = (b = 0);` , 就先计算 `b = 0` 的值;
2. 要计算 `b = 0` 的值, 就先计算 `0` 的值(就是 `0`);
3. 执行复制: 将 `0` 赋值给 `b` , 同时将 `0` 作为 `b = 0` 的返回值;
4. 执行复制: 将 `0` 赋值给 `a` , 同时将 `0` 作为 `a = (b = 0)` 的返回值;
5. 这个返回值被丢弃, 语句结束.

我们可以利用这个"返回值", 对一些操作进行简写:

```c
char c;
while ((c = getchar()) != EOF) {
    // ...
}
```

另外, 利用ASCII码, [第3点](#3-遍历字符串-时间复杂度)中, 字符串的遍历可以进一步简写:

```c
char str[] = "1  23  34 3 4 3 5 3";
int i;
int cnt = 0;
for (i = 0; str[i]; ++i) { // 原来是 for (i = 0; str[i] != '\0'; ++i) {
    if (str[i] == ' ') {
        ++cnt;
    }
}
```

这是因为 `'\0'` 的ASCII码就是 `0` , 因此当 `str[i]` 为逻辑假 (对应 `int` 值为 `0`), 就可以直接退出循环.
