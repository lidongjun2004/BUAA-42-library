## 关于`strlen`与`strcmp`的再次强调

### 不要在循环的判定条件里用`strlen`

仍然有同学这样遍历字符串, 真心担忧这些同学会不会因为这个而TLE? 特别是考试时...

```c
char str[100] = {0};
// store a string in str
int i;
for (i = 0; i < strlen(str); ++i) {
    // do something
}
```

你可以想象得到, `strlen` 函数的实现就是如下这样的:

```c
int strlen(char *s) {
    int i;
    for (i = 0; s[i] != '\0'; ++i) {
        // do nothing
    }
    return i;
}
```

也就是说`strlen`本来就是一个循环(时间复杂度 $O(n)$ ), 如果把它放在循环的判定条件里使用, 那就导致了 $O(n^2)$ 的时间复杂度.

**正确的做法如下!!!**

```c
char str[100] = {0};
// store a string in str
int i;
for (i = 0; str[i] != '\0'; ++i) {
    // do something
}
```

**除非你真的关心字符串长度, 请不要调用`strlen`!**

## 关于自主构造尽可能周到的测试样例

最近发现有些同学是**面向评测机编程**的...

我们可以把C程序划分为若干个函数, 每个函数又由若干分支语句和若干跳转语句组织形成的.

提出以下基本测试方法.

**函数基本测试:**

1. 构造一系列测试样例, 使得每一个分支和循环都被执行至少一次;
2. 如果遇到函数调用, 应当对被调用函数进行**函数基本测试**.

> 这样的测试是*递归的过程*.

**当然, 某些同学题目要求都没看清就开始做题, 用这种测试方法是没法查出来的.**
