## 不规范的编程习惯

### 设置了返回值类型, 但没有写返回值

有些同学设计函数时, 声明了其返回值类型为 `int` , 但函数体内存在某些执行顺序(分支), 其内没有返回 `int` 型的数据. 类似如下的编写:

```c
int func(int x) {
    if (x >= 0) return x * x;
}
```

就存在 `x < 0` 的情况, 使得函数没有显式 `return` 任何值. 这样的编写是可以通过编译的, 但是在开启了O2优化(GCC编译优化)时, **其编译结果可能与编写者的本意不符**.

恰好, 我们的OJ系统就默认开启了O2编译, 因此有一些同学就在这样的细节上无法通过评测.

### `fgets` 读到的字符串中, 最后一个字符一定是 `\n` 吗?

有些同学习惯编写如下的代码段:

```c
char s[1024];
fgets(s, 1024, stdin);
s[strlen(s) - 1] = '\0'; // 去除 '\n'
```

请注意, `fgets` 输入到的字符串有可能不以 `'\n'` 结尾. 比如当前行是文件的最后一行, 其后应该直接就是 `EOF` , 并没有 `'\n'` , 此时若像上述代码一样操作, 将导致最后一个字符被误覆盖.

值得注意的是, 尽管采用控制台输入( `stdin` ), 也不能保证最后一个字符为 `'\n'` , 因为可以通过键入 `CTRL+Z` 等方式模拟 `EOF` . 所以同学们不要再使用上面的代码方式进行读入处理了.

### 重叠区域中 `strcat` 与 `strcpy` 的不可预测行为

根据C标准, `strcat` 与 `strcpy` 操作的内存空间不应属于同一字符串区域, 否则将导致不可预测的结果.

## `fgetc` 不能作试探

`fgetc` 是不能作试探的. 即 `fgetc` 读到的字符, 下一次 `fgetc` 将不会再读到. 这一性质在其他读入函数中也是存在的, 所以请不要使用读入函数向前看字符.

> 如果非要向前看字符, 可以考虑搭配 `ungetc` 函数使用, 有兴趣的同学请自行查资料了解.

## 不熟练文件IO

依然有同学对文件操作函数不熟悉, 这部分内容可以参考第3期猪脚说.

这里提一下有关文件路径的事情. 在 `fopen` 中, 第一个参数为需要打开的文件的路径, **要么填写相对路径, 要么填写绝对路径**. 以Windows操作系统为例, 考虑如下的文件目录结构:

> 鉴于OJ评测机制, 我们要求大家必须使用如下的**相对路径**写法.

```text
D:
|- buaa
    |- grade1
        |- DSP
            |- Stack.pptx
        |- MA
            |- Integral.pptx
            |- Differential.pptx
    |- grade2
|- code
    |- main.c
    |- file.txt
```

使用Dev-C++编译code文件夹下的main.c, 将在code文件夹中生成exe文件:

```text
D:
|- buaa
    |- grade1
        |- DSP
            |- Stack.pptx
        |- MA
            |- Integral.pptx
            |- Differential.pptx
    |- grade2
|- code
    |- main.c
    |- main.exe
    |- file.txt
```

如果main.c代码中, 需要打开main.exe同目录下的file.txt文件, 则只需要这样编写:

```c
FILE *fp = fopen("file.txt", "r"); // read-only
```

**强调: 相对路径中的 *相对* 应当是与exe文件 *相对* , 一般而言Dev-C++编译出来的exe文件就与c文件在同一目录下, 所以一般情况下可以认为是与c文件 *相对***
