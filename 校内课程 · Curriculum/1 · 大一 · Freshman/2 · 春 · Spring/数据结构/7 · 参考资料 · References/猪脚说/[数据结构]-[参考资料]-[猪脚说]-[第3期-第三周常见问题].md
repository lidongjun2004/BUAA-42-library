<h2 id="1.1">使用未初始化的指针</h2>
未初始化的指针与其他未初始化的变量相同，其值不可预测；

对未初始化的指针进行取值操作会导致运行时错误，并且很难找到错误处；因此在使用指针时一定要注意程序使用指针的部分中指针是否已经初始化。
<h2 id="1.2">指针参数传递理解混乱</h2>
C语言中，所有函数在运行时能够使用的函数参数都是传入参数的一个拷贝；

使用变量的指针作为参数可以在函数内部修改变量的值是因为指针保存的是该变量的地址；传入后函数内部使用的参数是该地址的一个拷贝，因此函数仍然可以通过地址来修改变量的值。

但是由于该函数内部使用的参数是传入的指针的拷贝，因此不能修改作为函数参数的指针指向的对象。

```c
int a;
void fun(int* pointer) 
{
    //函数内部使用的参数
    *pointer = 2;
    pointer = &a;
}
int main()
{
    //变量
    int i = 3;
    //传入的参数
    int* p = &i;
    fun(p);
}
```

可以试着推断一下上面程序运行的结果。
<h2 id="1.3">数组初始化问题</h2>
c语言中数组的初始化可以通过花括号来进行，如：

```c
int a[19] = {0};
```

对于n维数组，应该使用n重花括号来初始化。

```c
int a[19][19][19] = {{{0}}}
```

当然，这种情况下也可以使用memset函数进行初始化。
<h2 id="1.4">memset函数使用问题</h2>
快速初始化数组可以使用memset函数，如下：

```c
int a[1000];
memset(a,0,sizeof(a));
```

现在a数组已经被全部初始化成了0。
但是这个函数的使用有一些需要注意的地方。首先是sizeof函数：

```c
char *s;
s = (char*)malloc(1000);
memset(s,0,sizeof(s));
```

这种情况下sizeof(s)会得到char型指针的大小。

因此在使用sizeof函数时要时刻注意传入的类型是数组还是指针。如果不能确定，可以使用:

```c
memset(s,0,1000*sizeof(char));
```

其次，应该避免使用memset初始化数组为0、-1以外的值。

这是因为在进行初始化之前，memset会把输入的数字（四字节）转换为一字节大小的unsigned char类型，并用这一字节去填满从传入的指针开始的指定大小的空间。

0转化为一字节后还是0，所以不会出现问题；

如果同学们还记得补码的相关知识的话，应该还记得-1在计算机中的表示是0xffffffff；

其转化为一字节后变成0xff，用这个字节填满空间后进行读取得到的还是0xffffffff，即-1。

可以尝试思考一下memset可以用来进行什么样的初始化？

对于字符串来说，这个限制还存在吗？对于int数组来说，使用memset能初始化的最大值是多少？

<h2 id="1.5">循环内的跳过、删除问题</h2>

```c
int i;
for(i = 0; i < n; ++i)
{
    if (some_condition) 
    {
        ++i;
    }
    work();
}
```

这种代码中i可能会越界（超过n），导致程序意外出错。

```c
char s[100];
int i, j;
int n = strlen(s);
for(i = 0; i < n; ++i)
{
    if (some_condition)
    {
        for(j = i;j < n - 1;++j)
        {
            s[j] = s[j + 1];
        }
    }
}
```

这段代码有两个问题：

1. 没有将字符串末尾的'\0'左移；
2. 在删除s[i]之后不会对移动到i处的s[i + 1]进行判断。

<h2 id="1.6">文件相关函数综述</h2>

在一般情况下，下文中"推荐使用"部分的几个函数已经可以满足当前所有的文件输入输出需求。

如果你愿意了解更多，可以向下查阅。

---

*以下函数参数列表中`char*`可以大致理解为字符串*

*`FILE*`可以大致理解为文件*

*为了便于理解，省略了大部分const修饰符，并人为修改了一些参数类型。*

---

**推荐使用：**

* `fopen(char* filename, char* mode)`和`fclose(FILE* stream)`
  * 打开和关闭文件的函数。前者返回一个FILE类型的指针，后者接受一个FILE*类型的指针并关闭它。
  * 是文件读入的基础函数。
  * 一般来说fopen的mode参数只需要使用"r"（读入）与"w"（写入）两种。
  * 在程序末尾使用fclose关闭输入输出文件可以让你的程序更可靠。推荐使用。
  * fopen在失败时返回*NULL（空指针）*，fclose则返回*EOF*。
* `fscanf(FILE* stream, char* format,...)`和`fprintf(FILE* stream, char* format,...)`
  * 和基础输入输出scanf、printf的用法和行为都几乎一样。
  * 需要结合fopen函数使用。
  * 在读到文件末尾时，fscanf返回*EOF*。
* `fgets (char* str, int num, FILE* stream)`和`fputs (char* str, FILE* stream)`
  * 读入一整行字符串，不会因为空格停止读入。与gets函数相似。
  * 读入的最大长度为num。
  * 在读到文件末尾时，fgets返回*空指针NULL*。
  * 请注意：如果混用fscanf和fgets，fgets可能会读入fscanf当作分隔符而没有读入的换行符。
  * fputs函数与puts函数相似，输出一整个字符串。

---
**可以使用，但是需要额外注意：**

* `freopen (char * filename,char* mode, FILE* stream )`
  * 将参数中传入的流重定向到文件流。
  * 如果在stream处填入stdin，则重定向后可以用标准输入输出的方式(如scanf，gets)来读写文件。
  * freopen失败时返回*空指针NULL*。
  * 由于操作系统的差别，**不应该**在使用freopen打开文件后再次使用freopen返回标准输入输出。
  * freopen可以作为调试时的选择之一。
* `fgetc(FILE* stream)`和`fputc(char character, FILE* stream)`
  * 与getchar和putchar近似，从文件里读入或输出单一字符。
  * 在读到末尾时，fgetc返回*EOF*。
  * getc和putc函数和这两个函数行为上没有区别，但是为了防止混淆，此处不予列出。

---
**基本不会使用到：**

* `fread(void* ptr, size_t size, size_t count, FILE* stream )`和`fwrite(void * ptr, size_t size, size_t count, FILE* stream)`
  * 从文件中读入或输出一整块数据。
  * 在读到末尾时，fread仍然会返回已读入数据的数量（依照size参数计算）。
  * 需要通过ferror、feof等判断是否读完。
  * **除非你知道自己在做什么，否则不应该使用这两个函数。**
  * 这两个函数的文件读写速度要高于其他函数，在对性能有所要求时可以考虑。
* `fflush(FILE* stream)`
  * 如果该输出流中有缓存的未输出数据，将其写入对应的文件。
  * 可以配合fwrite等函数工作。
  * 一般来说不会用到。
  * 错误时返回EOF。

---
**不推荐使用**

* `feof(FILE* stream)`和`ferror(FILE* stream)`
  * 可以用来判断文件是否读取完毕，或是找出文件读取时的错误。
  * 经测试在Windows系统和Linux系统上的行为有区别。
  * **除非你知道自己在做什么，否则不应该使用这两个函数。**
* `ftell`，`fseek`，`fgetpos`，`fsetpos`和`rewind`:
  * 文件读取或写入时操作写入位置的函数。
  * 可以配合fread和fwrite使用。
  * **除非你知道自己在做什么，否则不应该使用这五个函数。**
