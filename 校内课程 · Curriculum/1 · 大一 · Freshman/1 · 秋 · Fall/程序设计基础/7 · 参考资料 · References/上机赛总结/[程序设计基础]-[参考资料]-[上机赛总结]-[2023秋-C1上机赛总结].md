# 第一次上机赛总结

## 一.有关语法

1. ```c++
   scanf("%d", a); //错误示范
   ```

   不加取址符 `&` ，会引起各种奇奇怪怪的问题

   双引号不要括住逗号后面的东西

2. ``` c++
   if(a > b)
       b = a;
    a = b;
   ```

   此写法等价于

   ``` c++
   if(a > b){
       b = a;
   }
   a = b;
   ```

   `if` 语句后如果不加大括号，只会执行第一条末尾带 `;` 的语句

   如果需要在if后执行多条语句，需要大括号`{` 和`}` 将语句括起来

   当然如果不喜欢多行或者括号，可以写成这样：

   ```c++
   if(a > b) b = a, a = b;//语句之间以逗号连接
   ```

3. ```c++
   for(int i = 1; i <= n; i++);//错误示范
   ```

   ```c++
   int i = 1;
   while(i <= n);//错误示范
   {
       //do something
       i++;
   }
   ```

   以上语句中 `for` 和 `while` 后面不要加 `;` ，否则会死循环

4. 关于`=` 和`==` ：

   `=` 是**赋值**运算，而 `==` 是条件**判断**，不要混用了。正确示范：

   ```c++
   if(a == b) c = d;
   ```

5. ```c++
   for(int i = 1; i <= n; i++){
       scanf("%d", &i);//错误示范
   }
   ```

   `i` 如果作为**循环变量** ，是不能再把数存到其中的，这会导致循环错乱或者死循环

6. `0` 作为除数和模数，有些编译器会有警告但不会报错，容易引起忽略，请在运算之前判断

7. 如果你的代码在输入数据之后一段时间无反应，并且无法读入任何东西，请考虑第1、3条

### 二.有关数据范围

题目给出的数据范围不需要输入到代码里，而是为了让你们自行考虑一些事情。比如：

1.是否超出 `int` ，`long long` 等类型的精度（自行查阅）

2.多重循环嵌套是否会超出时间限制

3.多维数组是否会超出空间限制

### 三.有关OJ

1. 诸如WA、TLE、REG等缩写代表什么请参考第一次上机赛**赛事简介**

2. 有时候你和AC代码一模一样，交上去却没有AC，建议再次提交，很有可能是太多人同时交代码导致评测姬脑子进水。如果还是不对，请仔细检查是否有**细节**错误

3. DevC保存代码按照**默认**的后缀`.cpp` 保存就好，如果使用`.c`，请注意

   ```cpp
   for(int i = 1; i<= n; i++)
   ```

   这种在 `for` 中定义变量的写法在C89是不被允许的，所以不会通过编译。（但我们的评测姬会默许

   可以通过 **工具->编译选项->代码生成/优化->语言标准(-std)->ISO C99** 更改

### 四.一些建议

1.每次比赛前把标准模板打好，开n个窗口复制粘贴，命名ABCD...，过一个关一个，可以有效节省时间

2.善用 **快捷键** 也可以有效节省时间

| 快捷键 | 功能 |
| --- | --- |
| Ctrl + A | 全选 |
| Ctrl + C | 复制 |
| Ctrl + V | 粘贴 |
| Alt + Tab | 切换到上一应用窗口 |

3.带一个鼠标和鼠标垫（书），没地方放可以放腿上，还可以有效节省时间

4.代码没过编译或者没有AC，不要第一时间提问，好好捋一下自己代码，细心找错，适当时候善用调试功能

5.不要着急抢有插口的位置，带个排插就能解决问题

6.如果没有对自己码力的绝对自信，请最好不要在AK之前打游戏

7.觉得题目难可以多看看每道题的**通过率**和**正确率**，优先找简单的做

8.能在题面上**复制粘贴**的字符串尽量不要手打

9.爱护自己以及老师助教的眼睛，界面字体稍微大一点...

10.形成良好的代码风格，个人建议像上面给出的例子一样多打空格

#include<stdio.h>

#include<string.h>

 else return gcd(y, x % y);
