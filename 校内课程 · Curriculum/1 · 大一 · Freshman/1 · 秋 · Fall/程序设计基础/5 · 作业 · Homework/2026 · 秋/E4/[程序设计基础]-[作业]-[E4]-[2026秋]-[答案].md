## A 打印店的优惠

| 难度 | 考点 |

### 题目

#### 题目描述

小 M 到打印店打印资料。打印店按以下规则收取费用：
前 20 页，每页 2 元； 超过 20 页的部分，每页 1 元。
例如，打印 25 页的费用为 20× 2+5× 1=45 元。优惠只作用于超过 20 页的部分。给定需要打印的页数 n，请计算总费用。如果打印 0 页，费用为 0 元。

#### 输入

第一行为一个整数 T (1≤ T≤ 10000)，表示数据组数。
接下来 T 行，每行一个整数 n (0≤ n≤ 10000)，表示需要打印的页数。每组数据独立计费。

#### 输出

对于每组数据，输出一行一个整数，表示总费用，单位为元。

#### 输入样例

```text
5
0
1
20
21
25
```

#### 输出样例

```text
0
2
40
41
45
```

author: 只只小木条

### 答案

### 解题思路

先把规则翻译成两个分支，再分别写计算式。

当 $n \le 20$ 时，每一页都是 $2$ 元，费用为 $2n$ ；当 $n > 20$ 时，前 $20$ 页固定为 $40$ 元，剩余 $n - 20$ 页各 $1$ 元，费用为 $40 + n - 20$ 。

两个分支分别处理“不超过 20 页”和“超过 20 页”，覆盖所有合法输入，且不会重复处理。 $n = 0$ 也自然得到 $0$ 。

### 示例代码

```c
#include <stdio.h>
int main() {
    int T;
    scanf("%d", &T);
    while (T--) {
        int n, cost;
        scanf("%d", &n);
        if (n <= 20) {
            cost = n * 2;
        } else {
            cost = 40 + (n - 20);
        }
        printf("%d\n", cost);
    }
    return 0;
}
```

### 题目

#### 题目描述

北京的秋天来了，但是很快又走了！外面实在太凉，你并不想离开你温暖的被窝，但你仍然想知道外面
刮的“秋风”的风向是什么。


```text
0 -5
```

### 答案

本题考查分支语句的应用。

### 解题思路 1：分类讨论

根据题意，直接用九个 `if-else` 分支语句判断输入属于九个情况中的哪个，或用分支套分支判断。

#### 示例代码 1

```c
#include<stdio.h>

int a,b;
int main(){
    scanf("%d%d",&a,&b);
    if(a>0){
        if(b>0) puts("northeast");
        else if(b<0) puts("northwest");
        else puts("north");
    }else if(a<0){
        if(b>0) puts("southeast");
        else if(b<0) puts("southwest");
        else puts("south");
    }else{
        if(b>0) puts("east");
        else if(b<0) puts("west");
        else puts("none");
    }
    return 0;
}
```

### 解题思路 2：分段输出

注意到输出字符串除了 `none` 总可以分成两个部分： `[north/south/空][west/east/空]` 。例如 `southwest` 相当于 `south+west` ， `north` 相当于 `north+空` ， `east` 相当于 `空+east` 。

所以我们可以分别判断两个部分应该输出什么，将两个部分拼接起来输出。需要特判掉 `none` 的情况。

#### 示例代码 2

```c
#include<stdio.h>

int a,b;
int main(){
    scanf("%d%d",&a,&b);
    if(a==0&&b==0) puts("none");
    if(a>0) printf("north");
    if(a<0) printf("south");
    if(b>0) printf("east");
    if(b<0) printf("west");
    return 0;
}
```

## C 67 numbers

| 难度 | 考点 |
| --- | --- |
| 2 | 循环、枚举、十进制数位分解 |

### 题目

#### 题目描述

我们说一个数字是67数，当且仅当它是正整数且十进制表述中至少有两个连续的数位是数字 67。例如
，67,671,1234567,6767 是67数；而 607,76,76076123,132 都不是67数。当一个数里有多个 67 时，它只算作一个67数。找出前 n 个67数。

#### 输入

一行一个正整数，表示 n。
数据保证 1≤ n≤ 6767。

#### 输出

输出 n 行。第 i 行的数表示第 i 个67数。

#### 输入样例

```text
10
```

#### 输出样例

```text
67
167
267
367
467
567
667
670
671
672
```

#### 提示

可以证明，连续的 100 正整数里至少有 1 个67数。（证明是平凡的。）
因此，因为数据保证 n≤6767，所以你输出的数不会超过 676700。此时可以发现，数字位数不超过 6。一个数字的后两位可以用 a % 100 提取出来。使用 a / 10 可以达到十进制上右移一位的效果。例：123 %100 可以得到 23，123 / 10 则可以提出 12。实际上，第 6767 个67数是 167763。

### 答案

### 解题思路

按照从小到大的顺序枚举正整数，并判断它的十进制表示中是否出现了连续的数字 `67` 。每找到一个 67 数就将计数器加一并输出，直到输出了前 $n$ 个 67 数为止。

判断一个整数是否为 67 数时，可以反复考察它的末两位。 `x % 100` 可以得到当前数字的末两位；如果结果等于 `67` ，说明找到了连续的 `67` 。否则执行 `x /= 10` ，删去个位后继续检查。一个数中即使出现了多个 `67` ，判断函数也只返回一次，因此它仍然只会被输出一次。

题目保证 $n \le 6767$ ，并提示连续的 $100$ 个正整数中至少存在一个 67 数，所以枚举范围足以在较短时间内完成。若最后输出的数为 $M$ ，时间复杂度为 $O(M \log M)$ ，额外空间复杂度为 $O(1)$ 。

### 示例代码

```c
#include <stdio.h>

int is_67_number(int x) {
    while (x > 0) {
        if (x % 100 == 67) {
            return 1;
        }
        x /= 10;
    }
    return 0;
}

int main() {
    int n;
    scanf("%d", &n);

    int count = 0;
    for (int x = 1; count < n; x++) {
        if (is_67_number(x)) {
            printf("%d\n", x);
            count++;
        }
    }

    return 0;
}
```

## D 娜娜爬楼梯

| 难度 | 考点 |
| --- | --- |
| 3 | 数组、递推、整数类型 |

### 题目

#### 题目描述

娜娜 要爬一段有 n 级台阶的楼梯，她从地面（第 0 级）出发，每次可以迈 1 级、2 级或 3 级，并且要正好踏上第 n 级台阶，一共有多少种走法？两种走法只要任意一次迈的级数不同，就算不同的走法。例如爬 3 级台阶： · 1 + 1 + 1（三次各迈 1 级）； · 1 + 2、2 + 1（一次 1 级、一次 2 级）； · 3（一次迈 3 级）。一共 4 种。

#### 输入

一行一个整数 n，保证 1 ≤ n ≤ 60。

#### 输出

一行一个整数，表示走法的总数。

#### 输入样例

```text
3
```

#### 输出样例

```text
4
```

### 答案

### 解题思路

设 `f[i]` 表示从第 $0$ 级出发，正好到达第 $i$ 级台阶的走法数。最后一次可能迈 $1$ 级、 $2$ 级或 $3$ 级，因此所有走法可以按照最后一步的长度分成三类：

$$
f[i] = f[i - 1] + f[i - 2] + f[i - 3].
$$

为了统一处理边界，令 `f[0] = 1` ，表示停在地面、不迈任何一步有一种方案。计算 `f[i]` 时，只累加下标不小于 $0$ 的状态。这样就不需要分别手写 `f[1]` 、 `f[2]` 和 `f[3]` 的初值。

$n \le 60$ 时答案可能超过 `int` 的范围，但仍能用 `long long` 保存。依次计算 `f[1]` 到 `f[n]` 即可。

时间复杂度为 $O(n)$ ，空间复杂度为 $O(n)$ 。

### 示例代码

```c
#include <stdio.h>

long long f[65];

int main() {
    int n;
    scanf("%d", &n);

    f[0] = 1;
    for (int i = 1; i <= n; i++) {
        for (int step = 1; step <= 3; step++) {
            if (i >= step) {
                f[i] += f[i - step];
            }
        }
    }

    printf("%lld\n", f[n]);
    return 0;
}
```

### 题目

#### 题目背景

如果想明白了的话，Hint 里面的每一句话都是非常有用的。无论想明白没有，Not Hint 里面的每一句话都是不错的课外拓展材料。洛谷（luogu.com.cn）是国内知名的算法竞赛在线评测平台与编程学习社区，创建于2013年。它面向算法竞赛选手和编程爱好者，提供从入门到 NOI/IOI 难度的海量题库，并集在线评测、题解交流、比赛训练及网校课程于一体。截至2025年底，用户已超200万，是国内信息学竞赛领域最具影响力的平台之一。对于洛谷的老用户而言，洛谷首页的打卡机制可谓是非常有趣了。

#### 题目描述

本题仅仅聚焦洛谷打卡机制的连续打卡天数规则。
具体而言，一位新用户注册时，其连续打卡天数 d1 默认为 0。其后，每打卡一天，连续打卡天数增加
1。
与其它网站忘记打卡则天数清零不一样，洛谷的连续打卡天数遵循如下规则：如果某天用户没有打卡，
则最新连续未打卡天数加一。当用户重新打卡时，若最新连续未打卡天数为 d2，则会按幂律规律扣除
连续打卡天数，具体而言，d1*=d1-2d_{2-1}。注意，d1* 未包含用户当日的打卡记录，即当日打卡后
，实际连续打卡天数为 (d1*+1)。
如果 2d_{2-1}>d1，那么 d1* 将会被设置为 0。避免出现连续未打卡天数过多，导致这辈子也不可能
把连续打开天数变为正数的情况发生。
我们用 1 表示当天打卡了，而用 0 表示当天没有打卡，则打卡记录
1111001110000000111
· 前四天都打卡了，因此第四天结束时连续打卡天数 d1=4。
· 第五第六两天忘记打卡，d2=2。

- 第七天打卡时，d1*=d1-2d_{2-1}=4-22-1=4-2=2。注意，第七天实际显示的连续打卡天数 d1=d1* +1=3。
- 第八第九天连续打卡，因此第九天时连续打卡天数 d1=3+2=5。
- 第 10 到第 16 天均未打卡，连续未打卡天数 d2=7。
- 第 17 天恢复打卡，d1*=d1-2d_{2-1}=5-27-1=5-26=5-64=-59<0，因此 d1* 被设置为 0。因此，第 17 天打卡后，实际显示的连续打卡天数 d1=d1*+1=1。
- 第 18 和第 19 天均打卡，连续打卡天数分别为 2,3。现在，给定洛谷某新注册用户在注册后连续 n 天的打卡情况，你需要求出每一天洛谷首页显示的连续打卡天数。注意，如果某天没有打卡，那么首页就自然不会显示连续打卡天数。此时，连续打卡天数按 0 计算。例如，上述例子中每一天的连续打卡天数是 1,2,3,4,0,0,3,4,5,0,0,0,0,0,0,0,1,2,3。

#### 输入格式

第一行，一个正整数，表示打卡天数 n。
第二行一个长度为 n 的、仅有 01 构成的字符串，表示每天的打卡情况。其中 0 表示未打卡，1 表示已打卡。保证 1 ≤ n ≤ 1 × 106。

#### 输出格式

假设每一天的连续打卡天数为 pi，那么你需要分别求出以下三个参数：

1. $\max\limits_{i=1}^{n} [p_i]$。即连续打卡天数的最大值。2. $\bigoplus\limits_{i=1}^{n} p_i$。即 n 天的连续打卡天数的异或和。即 p1 ⊕ p2 ⊕ p3 ⊕ … ⊕ pn。其中 a ⊕ b 表示 a 和 b 按位异或的结果。3 . ( ∑limitsi=1n ipi ) mod 998244353。即 p1+2p2+3p3+… npn 的和对 998244353 取模的结果。输出三行，每行一个整数，按顺序分别表示以上三个参数。

### 答案

### 解题思路

总体思路就是按照题目意思去模拟即可。

以下是需要注意的地方：

1. 由于连续未打卡天数可能很多（第 $10$ 个测试数据专门针对此情况，连续 $(3 \times 10^5)$ 天未打卡），如果就这么硬算 $2^{3 \times 10^5}$ 的话，什么类型也装不下（long long 也才 $2^{63} - 1$ ）。

   但是，我们发现，如果连续未打卡天数 $d_2$ 已经使得 $2^{d_2 - 1} > d_1$ ，即已经使连续打卡天数减少到 $0$ 以下了，那么这个时候 $d_2$ 再累加已经没有意义了（反正结果就是 $d_1$ 被清零了）。既然结果都一样，那我们就没有必要去累加 $d_2$ 了。 $d_1$ 不会超过 $n$ ， $n \le 1 \times 10^6$ ，而 Hint 里给出 $2^{21-1} > 1 \times 10^6$ ，因此当 $d_2 \ge 21$ 时，就没有必要再累加了。

1. $p_i$ 最大可能达到 $n$ ，即 $10^6$ 的量级，下标 $i$ 也可能达到这个量级，因此 $ip_i$ 可能会爆 int。第 $9$ 第 $10$ 测试点卡爆 int 的问题。

考虑到同学们可能有多种写法，助教写了四份标程供大家参考（头文件省略）。

### 示例代码 1

```c
#define mod 998244353

int ans1,ans2,ans3,cnt,res,n;

int main(){
    scanf("%d",&n);

    for(int i=1;i<=n;i++){
        int cur;
        scanf("%1d",&cur);

        if (cur==1){
            if (cnt>0) res=res-(1<<(cnt-1));
            if (res<0) res=0;
            //注意必须用括号提高左移运算符的优先级（位运算的优先级很低，远低于加减乘除）

            res++;
            cnt=0;//注意清空未打卡天数

            if (res>ans1) ans1=res;
            ans2^=res;
            ans3=(ans3+1ll*i*res%mod)%mod;
            //注意 i*res 可能会爆 int
        }
        else{
            if (cnt<=21) cnt++;
            //如果连续未打卡天数 >21，最后效果都是 res 被清零，没有区别

            //未打卡时认为连续打卡天数为 0，三个参数的值都不变
        }
    }

    printf("%d\n%d\n%d",ans1,ans2,ans3);

    return 0;
}
```

### 示例代码 2

```c
#define mod 998244353

int ans1,ans2,ans3,res,cnt,n;

int main(){
    scanf("%d\n",&n);
    //干掉多余的换行等空白字符

    for(int i=1;i<=n;i++){
        int cur=getchar()-'0';

        if (cur==1){
            if (cnt>0) res=res-(1<<(cnt-1));
            if (res<0) res=0;

            res++;

            cnt=0;

            if (res>ans1) ans1=res;
            ans2^=res;
            ans3=(ans3+(long long)i*res%mod)%mod;
        }
        else{
            if (cnt==0||(1<<(cnt-1))<=res) cnt++;
            //如果 2^(cnt-1)>res 了，那么再往上加没有意义了
```

### 题目

#### 题目描述

给定一个合法的公历日期和一个非负整数 k，请计算从该日期向后经过 k 天的日期。k=0 时，答案就是输入的日期；k=1 时，答案就是输入日期的下一天。各组询问相互独立。本题中的所有日期均按以下公历规则计算： · 1,3,5,7,8,10,12 月各有 31 天。 · 4,6,9,11 月各有 30 天。 · 平年的 2 月有 28 天，闰年的 2 月有 29 天。 · 年份能被 400 整除，或者能被 4 整除但不能被 100 整除时，该年为闰年；否则为平年。

#### 输入

第一行，一个正整数 t，表示询问组数，满足 1 ≤ t ≤ 1000。
接下来 t 行，每行包含四个由空格分隔的整数 y,m,d,k，分别表示输入日期的年份、月份、日和向后
经过的天数，满足 1600 ≤ y ≤ 9999，1 ≤ m ≤ 12，1 ≤ d ≤ 31，0 ≤ k ≤ 1000。保证输入的日期合法，即 d 不超过该年该月的天数；保证答案的年份不超过 9999。

#### 输出

输出 t 行，按照输入顺序，每行输出三个由空格分隔的整数，依次表示答案的年份、月份和日，不补
前导零。答案满足年份在 [1600,9999] 内、月份在 [1,12] 内，日不小于 1 且不超过该年该月的天数。

#### 输入样例 1

```text

2026 10 8 1
2026 4 30 1
2026 7 31 1
2023 2 28 1
2024 2 28 1
2024 2 29 1
2024 12 31 1
```

#### 输出样例 1

```text

2026 10 9
2026 5 1
2026 8 1

2024 2 29
2024 3 1
2025 1 1
```

#### 输入样例 2

```text
7
1600 2 28 2
1700 2 28 1
2000 2 28 1
2100 2 28 1
2023 12 31 366
2024 1 1 366
9999 12 30 1
```

#### 输出样例 2

```text

1700 3 1
2000 2 29
2100 3 1
2024 12 31
2025 1 1
9999 12 31
```

#### 样例解释

2024 年是闰年，因此 2024 年 2 月 28 日的下一天是 2 月 29 日，再过一天是 3 月 1 日。 1700 年和 2100 年虽然能被 4 整除，但能被 100 整除且不能被 400 整除，因此是平年。1600 年和 2000 年能被 400 整除，因此是闰年。

### 答案

### 解题思路

由于 $0 \le k \le 1000$ ，可以直接模拟日期向后移动的过程，每次移动一天，共移动 $k$ 天。

首先使用数组 `days` 存储每个月的天数。二月的天数与当前年份有关，因此每次移动日期前，根据闰年规则更新 `days[2]` ：

- 如果年份能被 $400$ 整除，或者能被 $4$ 整除但不能被 $100$ 整除，则二月有 $29$ 天。

- 否则二月有 $28$ 天。

接下来将日期中的 `d` 加一。如果 `d` 超过当月天数，就将 `d` 设为 $1$ ，月份 `m` 加一。如果月份超过 $12$ ，就将 `m` 设为 $1$ ，年份 `y` 加一。

重复上述过程 $k$ 次即可得到答案。每组询问最多模拟 $k$ 天，每天进行常数次操作，时间复杂度为 $O(k)$ ，额外空间复杂度为 $O(1)$ 。

### 示例代码

```c
#include <stdio.h>

int days[13] = {0, 31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31};

int main() {
    int t;
    scanf("%d", &t);

    while (t--) {
        int y, m, d, k;
        scanf("%d%d%d%d", &y, &m, &d, &k);

        while (k--) {
            if (y % 400 == 0 || (y % 4 == 0 && y % 100 != 0)) {
                days[2] = 29;
            } else {
                days[2] = 28;
            }

            d++;
            if (d > days[m]) {
                d = 1;
                m++;
                if (m > 12) {
                    m = 1;
                    y++;
                }
            }
        }

        printf("%d %d %d\n", y, m, d);
    }
    return 0;
}
```

### 答案

### 解题思路

这个题要实现的功能较为复杂，很多同学可能感到无从下手，或者感到十分难写、难以 debug。下面教同学们如何思路清晰地解决这道题。

---

首先理清题意，设计一个比较粗糙的程序流程。样例解释提示了这样一个程序流程：

1. 求出输入的像素塔时间与 `72.B.P. 8 月 32 日 12:00:00` 相距多少像素秒。

1. 将这个值除以 `377` 并四舍五入，得到答案相对 `公元 2089 年 5 月 11 日 00:00:00` 经过了多少秒。

1. 设经过了 $x$ 秒，求 `公元 2089 年 5 月 11 日 00:00:00` 经过 $x$ 秒后的时刻。

这里的难点在于 `72.B.P. 8 月 32 日 12:00:00` 和 `公元 2089 年 5 月 11 日 00:00:00` 都有零有整的，我们很难直接用它计算。下面我们细化这部分的流程。

---

对于第一步，一个比较简单的处理方法是：先手算出 `72.B.P. 8 月 32 日 12:00:00` 和 `72.B.P. 元旦 72.B.P. 1 月 1 日 00:00:00` 相距多少像素秒，设它为 $T$ （ $T = 21643200$ ）。在程序里，我们先计算输入的像素塔时间和上述的 `72.B.P.` 元旦相距多少像素秒，然后将它减去 $T$ ，就能得到输入的像素塔时间与 `72.B.P. 8 月 32 日 12:00:00` 相距多少像素秒。

对于第三步，处理方法是类似的。先手算出 `公元 2089 年 5 月 11 日 00:00:00` 和 2089 年元旦 `公元 2089 年 1 月 1 日 00:00:00` 相距多少秒，设它为 $T'$ （ $T' = 11232000$ ）。在程序里，我们将像素秒除以 `377` 并四舍五入后，再加上 $T'$ ，就能得到答案和上述的 2089 年元旦相距多少秒。

---

然后再细化一些具体实现的部分，写出最终的完整程序流程：

1. 求输入的像素塔时间和 `72.B.P.` 元旦 `72.B.P. 1 月 1 日 00:00:00` 相距多少像素秒，设它为 $\Delta T$ 。

   1. 先计算输入年份 $y$ 与 `72.B.P.` 相距的年份 $\Delta y$ 。如果 $y$ 是 `B.P.` 的，则距离是 $72 - y$ 年，否则是 $y + 71$ 年。

   1. 再计算输入的月、日和 `1 月 1 日` 相距的天数 $\Delta d$ 。这是简单的，设输入的是 $p$ 月 $q$ 日，我们可以枚举 $1$ 到 $p - 1$ 月，累加它们的天数，再将剩下的 $q$ 天加进去。

   1. 最后计算输入的时、分、秒与 `00:00:00` 相距的秒数 $\Delta s$ 。这同样是简单的，设输入的是 $h : m : s$ ，则 $\Delta s = 3600h + 60m + s$ 。

   1. 最终 $\Delta T = \Delta y \times (377 \times 24 \times 3600) + (\Delta d - 1) \times (24 \times 3600) + \Delta s$ 。（注意这里天数要 $-1$ ）

1. 将这个值减去 $21643200$ ，除以 $377$ 并四舍五入，再加上 $11232000$ ，得到答案相对 `公元 2089 年 1 月 1 日 00:00:00` 经过的秒数 $\Delta T'$ 。

1. 求 `公元 2089 年 1 月 1 日 00:00:00` 经过 $\Delta T'$ 秒到达的时刻。这一步并不困难，有多种做法，下面介绍一种比较简洁的基于整除和取模的做法。

   1. 因为现实世界一年等于 $365 \times 24 \times 3600 = 31536000$ 秒，所以 $\left\lfloor \dfrac{\Delta T'}{31536000} \right\rfloor$ 就是从 2089 年经过的年数， $\Delta T' \bmod 31536000$ 就是从 $2089 + \left\lfloor \dfrac{\Delta T'}{31536000} \right\rfloor$ 年元旦且经过的秒数。这里 $2089 + \left\lfloor \dfrac{\Delta T'}{31536000} \right\rfloor$ 年就是答案年。

   1. 因为现实世界一天等于 $86400$ 秒，所以 $\left\lfloor \dfrac{\Delta T' \bmod 31536000}{86400} \right\rfloor$ 就是从答案年元旦经过的天数， $(\Delta T' \bmod 31536000) \bmod 86400 = \Delta T' \bmod 86400$ 就是从答案年元旦经过的秒数。根据这个秒数很容易求出答案时、分、秒，只有天数需要额外转换到答案月、日。

   1. 下面根据天数求月、日。设天数为 $d$ ，我们从 $1$ 月开始枚举月份，不断累加经过的天数，如果枚举到 $i$ 月时总天数超过了 $d$ ，则答案月份就是 $i - 1$ ，答案日就是 $d$ 减去前 $i - 1$ 月的总天数再 $+1$ 。

---

这样我们就解决了这个问题，可以直接着手一步步实现了。以下是实现过程中可能遇到的一些问题：

1. 秒数可能很大，所以要用 `long long` 存储。

1. 如何对 `double` 四舍五入。一个简单的方法是直接将它加上 $0.5$ ，然后自然下取整。不难发现这是正确的。

---

这类题在《程序设计基础》课程的较难题里属于比较常见的类型。它们的本质并不困难，各种做法原则上都能实现得了，但其实现难度与你的思路关系非常大。对这种题我们应当"think twice, code once"，提前理清思路，理顺程序逻辑，设计易于实现的流程，然后再着手实现，可以大大降低实现难度。

### 示例代码

```c
#include<stdio.h>

const int days[12]={32,29,32,31,32,31,32,32,31,32,31,32};
int main(){
    int typ,yr,mo,dy,hr,mn,sec;
    while(~scanf("%d%d%d%d%d%d%d",&typ,&yr,&mo,&dy,&hr,&mn,&sec)){
        if(!typ) yr=72-yr;
        else yr+=71;
        long long tim=(long long)yr*32572800;
        for(int i=0;i<mo-1;i++) tim+=days[i]*86400;
        tim+=(dy-1)*86400;
        tim+=hr*3600+mn*60+sec;
        tim-=21643200;
        long long rtim=(long long)((double)tim/377+0.5)+11232000;
        int ayr=rtim/31536000+2089,totd=(rtim%31536000)/86400,ahr=(rtim%86400)/3600,amn=(rtim%3600)/60,asec=rtim%60;
        int curd=0,amo=0,ady=0;
        for(int i=0;i<12;i++){
            int nx=curd+days[i]-1;
            if(nx>totd){
                amo=i+1,ady=totd-curd+1;
                break;
            }
            curd=nx;
        }
        printf("%d-%02d-%02d %02d:%02d:%02d\n",ayr,amo,ady,ahr,amn,asec);
    }
    return 0;
}
```

## H 木桶蓄水

### 题目

你永远可以在LCYing出的题中读到最简单、最直白、最不绕弯子的题面。

#### 题目描述

有 n 块宽度均为 1 的木板，从左到右依次编号为 1,2,…,n，第 i 块木板的高度为正整数 hi。
你需要选择两块木板 i,j，满足 1≤ i<j≤ n，分别作为左边界和右边界。设水位高度为 t=min(hi,hj)，则两块木板之间的蓄水量定义为 W(i,j)=∑k=i+1j-1max(t-hk,0).[图]也就是说，对于两块边界之间的每块木板 k，若 h\_k<t，则它所在位置的蓄水量为 t-h\_k；否则，该位置的蓄水量为 0。若选中的两块木板相邻，则蓄水量为 0。请你求出选择两块木板能够得到的最大蓄水量。

#### 输入

第一行，一个正整数 n，满足 2≤ n≤ 3000。
第二行，包含 n 个正整数 h1,h2,…,hn，满足 1≤ hi≤ 109。

#### 输出

输出一个整数，表示能够得到的最大蓄水量。

#### 输入样例 1

```text
5
3
1
4
1
3
```

#### 输出样例 1

```text
4
```

#### 输入样例 2

```text
2
7
5
```

#### 输出样例 2

```text
0
```

#### 样例解释

对样例1：选择第 1 块和第 5 块木板作为边界，水位高度为 min(3,3)=3，蓄水量为 W(1,5)=max(3-1,0)+max(3-4,0)+max(3-1,0)=2+0+2=4. 其他选择均无法得到更大的蓄水量，因此答案为 4。

#### Hint

该题有 O(n),O(nlog{n}) 等做法，但本题已削弱为 O(n2) ，本题各种做法都可作为相关算法的入门题，感兴趣的同学可以自行研究如何优化。 Provider : LCYing

### 答案

### 解题思路

选择两块边界木板，使它们之间的蓄水量最大。

选定边界 $i, j$ 后，整个区间的水位由较低的边界 $t = \min(h_i, h_j)$ 决定。

区间内第 $k$ 块木板对这个区间的蓄水量贡献为 $\max(t - h_k, 0)$ ，即高于较低边界的木板贡献为 $0$ 。

#### $O(n^2)$ 算法：枚举较低的边界

#### 如何避免重复计算

如果枚举所有边界 $i, j$ ，再扫描它们之间的木板计算蓄水量，时间复杂度为 $O(n^3)$ 。

重复计算的原因在于：不同边界组合的水位可能不同，内部木板的贡献也随之改变。

我们可以换一个枚举方式：**先固定较低的边界，让水位保持不变。**

枚举木板 $i$ ，假设它是较低的边界，水位就固定为 $h_i$ 。另一块边界必须满足高度不小于 $h_i$ 。

先从 $i$ 的右侧向右扫描，维护变量 $water$ ，初始值为 $0$ 。扫描到木板 $j$ 之前，始终有

$$
water = \sum_{k=i+1}^{j-1} \max(h_i - h_k, 0).
$$

根据木板 $j$ 的高度，分两种情况处理：

- 如果 $h_j < h_i$ ，木板 $j$ 无法与 $i$ 组成水位为 $h_i$ 的边界，但可以成为后续区间的内部木板。因此，将 $h_i - h_j$ 加入 $water$ 。

- 如果 $h_j \ge h_i$ ，木板 $j$ 可以作为右边界。此时 $water$ 就是 $W(i, j)$ ，用它更新答案。木板 $j$ 在水位 $h_i$ 下的贡献为 $0$ ，不需要修改 $water$ 。

再从 $i$ 的左侧向左扫描，处理较低边界位于右侧的情况。注意，两个方向的 $water$ 应分别从 $0$ 开始计算。

#### 正确性说明

我们枚举了所有木板作为最短板的情况并更新答案，最优解一定是其中一种。

#### 复杂度分析

枚举每块木板，并分别向左右扫描，共访问 $n - 1$ 块木板。因此，时间复杂度为 $O(n^2)$ ，空间复杂度为 $O(n)$ 。

对于本题 $n \le 3000$ 的范围，这种方法已经足够。

### 示例代码

```c
#include <stdio.h>

int n;
long long h[3000], ans = 0;

int main()
{

    scanf("%d", &n);
    for (int i = 0; i < n; ++i)
    {
        scanf("%lld", &h[i]);
    }

    for (int i = 0; i < n; ++i)
    {
        long long water = 0;
        for (int j = i + 1; j < n; ++j)
        {
            if (h[j] >= h[i])
            {
                if (water > ans)
                {
                    ans = water;
                }
            }
            else
            {
                water += h[i] - h[j];
            }
        }

        water = 0;
        for (int j = i - 1; j >= 0; --j)
        {
            if (h[j] >= h[i])
            {
                if (water > ans)
                    ans = water;
            }
            else
            {
                water += h[i] - h[j];
            }
        }
    }

    printf("%lld\n", ans);
    return 0;
}
```

### 题目

#### 题目描述

给定正整数 a, b，求F(a, b) = ∑k = 0b - 1 [ a k/b ]的值。其中 \lfloor x \rfloor 表示 x 向下取整。

#### 输入格式

本题包含多组测试数据。
第一行一个整数 T (1 ≤ T ≤ 105) 表示测试数据组数。
接下来 T 行，每行两个正整数 a, b (1 ≤ a, b ≤ 109)。

#### 输出格式

对于每组数据，输出一行一个整数，表示 F(a, b) 的值。

#### 样例输入

```text
6
1 5
5 1
3 5
4 6
6 6
1000000000 1000000000
```

#### 样例输出

```text
0
0
4
8
15
499999999500000000
```

Author: ExplodingKonjac

### 答案

### 解题思路

直接枚举 $k$ 需要 $O(b)$ 的时间，无法处理本题的数据范围。

注意到 $k = 0$ 时对应的项为 $0$ ，只需考虑 $k = 1, 2, \ldots, b - 1$ 。将这些项正着写一遍，再倒着写一遍，首尾相加：

$$
2F(a, b) = \sum_{k=1}^{b-1}\left(\left\lfloor \frac{ak}{b} \right\rfloor + \left\lfloor \frac{a(b-k)}{b} \right\rfloor\right).
$$

括号内两个数在取整前的和为 $a$ 。如果 $ak$ 能被 $b$ 整除，两个数都是整数，取整后的和仍为 $a$ ；否则，两个数的小数部分之和为 $1$ ，取整后的和为 $a - 1$ 。因此

$$
\left\lfloor \frac{ak}{b} \right\rfloor + \left\lfloor \frac{a(b-k)}{b} \right\rfloor =
\begin{cases}
a, & b \mid ak, \\
a - 1, & b \nmid ak.
\end{cases}
$$

设 $d = \gcd(a, b)$ 。将 $a$ 和 $b$ 同时除以 $d$ 后，得到两个互质的整数，所以 $b$ 整除 $ak$ 等价于 $b/d$ 整除 $k$ 。在 $1$ 到 $b - 1$ 中，满足条件的 $k$ 恰好为

$$
\frac{b}{d},\ 2\frac{b}{d},\ \ldots,\ (d-1)\frac{b}{d},
$$

共 $d - 1$ 个；当 $d = 1$ 时没有这样的 $k$ 。

于是， $b - 1$ 个配对和都先按 $a - 1$ 计算，再为其中 $d - 1$ 个各加上 $1$ ，得到

$$
2F(a, b) = (a - 1)(b - 1) + d - 1,
$$

即

$$
F(a, b) = \frac{(a - 1)(b - 1) + \gcd(a, b) - 1}{2}.
$$

使用欧几里得算法求出 $d$ ，再代入公式即可。该公式同样适用于 $a = 1$ 或 $b = 1$ 的情况，此时答案为 $0$ 。

计算乘积前需要转换为 `long long` ，否则两个 `int` 相乘可能溢出。公式的分子不超过 $10^{18}$ ，可以使用 `long long` 存储。每组数据的答案都应独占一行。

### 示例代码

```c
#include <stdio.h>

int main(void) {
    int T;
    scanf("%d", &T);
    while (T--) {
        int a, b;
        scanf("%d%d", &a, &b);
        int x = a, y = b;
        while (y != 0) {
            int r = x % y;
            x = y;
            y = r;
        }
        printf("%lld\n", (1LL * (a - 1) * (b - 1) + x - 1) / 2);
    }
    return 0;
}
```

### 答案

### 解题思路

以下设值域上限为 $V$ 。

聪明的小朋友可能会想到 E3J，尝试使用类似那道题的拆位法解决该问题。遗憾的是基于拆位法只能得到一个 $O(n \log^2 V)$ 的做法，这个做法是相当难以通过的！

拆位法对按位与和按位或这两种运算的性质的利用是不够充分的。利用运算本身的性质，我们可以得到更优的做法。

---

考虑从小到大枚举区间的右端点 $r$ ，用变量 $cur$ 存区间 $[1, r], [2, r], \cdots, [r, r]$ 的价值之和，即所有右端点是 $r$ 的区间的价值之和。 $r$ 每增加 $1$ ，我们算出新增的 $a_{r+1}, b_{r+1}$ 对 $cur$ 的影响，更新 $cur$ 后将 $cur$ 累加到答案内。因为每个区间恰好会在 $r$ 枚举到其右端点时被统计，所以这能不重不漏地统计所有区间的价值。

问题转化为如何算出 $a_{r+1}, b_{r+1}$ 对 $cur$ 的影响。首先我们写出 $cur$ 的表达式。设 $A_i$ 为 $a_i \& a_{i+1} \& \cdots \& a_r$ ， $B_i = b_i | b_{i+1} | \cdots | b_r$ ，则 $cur = \sum_{i=1}^{r} A_i B_i$ 。然后考虑 $cur$ 受到的影响。加入 $a_{r+1}, b_{r+1}$ 后，它会对 $cur$ 造成以下两种影响：

- $A_{r+1}, B_{r+1}$ 被创建，初值分别为 $a_{r+1}, b_{r+1}$ 。它们为 $cur$ 贡献 $a_{r+1}b_{r+1}$ 。

- $A_1 \sim A_r$ 全部按位与上 $a_{r+1}$ ， $B_1 \sim B_r$ 全部按位或上 $a_{r+1}$ 。这部分对 $cur$ 的影响比较难计算，一个暴力的方法是枚举 $i = 1, 2, 3, \cdots, r$ ，对于每个 $i$ ，将 $cur$ 减去旧的 $A_i B_i$ ，再更新 $A_i, B_i$ ，最后将 $cur$ 加上 $A_i B_i$ 。

上述做法的时间复杂度是 $O(n^2)$ 的，无法通过。可以看到，这个做法的瓶颈在于暴力枚举 $1, 2, 3, \cdots, r$ 以更新 $A_1 \sim A_r$ 和 $B_1 \sim B_r$ ，下面我们来看这里是否有很多枚举是不必要的。

---

我们先来单独考虑某个 $A_i$ 的变化过程。右端点枚举到 $i$ 时， $A_i$ 被创建，初值为 $a_i$ ；枚举到 $i + 1$ 时， $A_i$ 按位与上 $a_{i+1}$ ，变为 $a_i \& a_{i+1}$ ；枚举到 $i + 2$ 时， $A_i$ 变为 $a_i \& a_{i+1} \& a_{i+2}$ ，以此类推。这个过程相当于 $A_i$ 的初值 $a_i$ 不断被按位与上一个数，每次右端点移动都会多按位与上一个数。

考虑到，**对于某一位，按位与只能使它从 $1$ 变成 $0$ ，而不能使它从 $0$ 变成 $1$ 。所以让一个数不断与上某些数，它的二进制表示中的 $1$ 会不断“单调地”被变成 $0$ ，这意味着它的值至多改变“二进制表示中 $1$ 的个数”次，即至多 $\lceil \log V \rceil = 30$ 次。所以每个 $A_i$ 的值只会被改变最多 $30$ 次。**

同时，不难发现这个结论对 $B_i$ 也是成立的。因为按位或恰好和按位与是反过来的，它只能使某一位从 $0$ 变成 $1$ ，而不能从 $1$ 变成 $0$ 。

所以说我们枚举所有 $i = 1, 2, 3, \cdots, r$ 是不必要的，**这些位置中可能有很多个 $A_i, B_i$ 均没有改变的 $i$ ，它们根本不需要被枚举**，需要被枚举的那些有用的 $i$ （即 $A_i, B_i$ 至少一个发生了改变的 $i$ ）实际上总共只有不超过 $2n\lceil \log V \rceil$ 个（形式化地讲，设对 $r$ 有用的 $i$ 有 $c_i$ 个， $\sum_{i=1}^{n} c_i \le 2n\lceil \log V \rceil$ ）。那么，在原来的 $O(n^2)$ 做法的基础上，如果我们能只枚举有用的 $i$ ，就可以获得一个 $O(n \log V)$ 的做法。

---

问题转化为如何只枚举这些 $i$ 。以 $A_i$ 为例，考虑什么时候 $A_i$ 按位与上一个数后不变。显然，如果某一个 $A_i$ 按位与上 $a_{r+1}$ 后不变，则 $A_1 \sim A_i$ 按位与上 $a_{r+1}$ 后都不变。**所以不变的 $A_i$ 一定构成一个前缀，这对不变的 $B_i$ 是一样的。** 也就是说对于 $i = 1, 2, 3, \cdots, r$ ，一定存在一个分界点，前面的 $i$ 都是没用的，后面的 $i$ 都是有用的。

所以解决方法实际上非常简单。我们从 $r$ 开始向前暴力枚举 $i = r, r - 1, r - 2, \cdots$ ，遇到第一个没用的 $i$ 时直接跳出循环即可。

时间复杂度 $O(n \log V)$ 。本题并不卡常数，任何写的不是特别丑的 $O(n \log V)$ 做法不使用快速读入也理应能通过。如果你过不了，可以尝试减少取模次数。

**Bonus** ：想一想，还有什么运算有类似的性质？（Hint：与你 P4 学习的内容有关！）

### 示例代码

```c
#include<stdio.h>

#define N 1000005
#define M 1000000007

int n,a[N],b[N];
int main(){
    scanf("%d",&n);
    for(int i=1;i<=n;i++) scanf("%d",&a[i]);
    for(int i=1;i<=n;i++) scanf("%d",&b[i]);
    long long ans=0,cur=0;
    for(int i=1;i<=n;i++){
        int p=i;
        while(--p){
            int A=a[p]&a[i],B=b[p]|b[i];
            if(A==a[p]&&B==b[p]) break;
            cur=(cur-(long long)a[p]*b[p]%M+(long long)A*B%M+M)%M;
            a[p]=A,b[p]=B;
        }
        cur=(cur+(long long)a[i]*b[i]%M)%M;
        ans=(ans+cur)%M;
    }
    printf("%lld\n",ans);
}
```
