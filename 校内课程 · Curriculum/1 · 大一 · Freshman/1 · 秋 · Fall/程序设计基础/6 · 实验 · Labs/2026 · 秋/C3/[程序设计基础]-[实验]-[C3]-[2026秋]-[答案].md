### 答案

### 题目分析

按照题目给出的顺序，依次计算 ~a 、 a & b 、 a | b 、 a ^ b 、 a << b 和 a >> b 即可。

~ 表示按位取反，即把每个二进制位上的 $0$ 变为 $1$，把 $1$ 变为 $0$。 & 、 | 、 ^ 分别表示按位与、按位或和按位异或。

a << b 把 $a$ 的 $32$ 位补码整体向左移动 $b$ 位，右侧补 $0$，移出的高位丢弃。为了明确保留低 $32$ 位，代码先把 $a$ 转换为 unsigned int 再左移，最后按题目要求转回有符号整数。

a >> b 表示右移。负数右移时左侧补符号位 $1$，即算术右移；非负数右移时左侧补 $0$。题目保证 $0 \le b \le 31$，所以移位数始终合法。

每组数据只需要常数次运算，时间复杂度为 $O(1)$，额外空间复杂度为 $O(1)$。

### 示例代码

```c
#include <stdio.h>
int main()
{
    int T;
    scanf("%d", &T);
    while (T--)
    {
        int a, b;
        scanf("%d%d", &a, &b);
        int left = (int)((unsigned int)a << b);
        int right = a >> b;
        printf("%d %d %d %d %d %d\n",
               ~a, a & b, a | b, a ^ b, left, right);
    }
    return 0;
}
```

### 答案

### 题目分析

题目要求输出整数 $x$ 的 $32$ 位补码，从最高的第 $31$ 位一直输出到最低的第 $0$ 位。

将 int 类型的 $x$ 转换为 unsigned int 后，它的 $32$ 个二进制位保持不变，但右移时会在左侧补 $0$。因此，对于第 $i$ 位，可以使用 (bits >> i) & 1U 先把它移到最低位，再用按位与取出这一位。结果一定是 $0$ 或 $1$。从 $i = 31$ 到 $i = 0$ 循环输出，中间不输出空格，最后再换行。

转换为无符号整数也能自然处理负数。例如 $-1$ 的 $32$ 位补码全为 $1$，转换后得到的无符号数也恰好是二进制下的 $32$ 个 $1$。

每组数据固定检查 $32$ 位，时间复杂度为 $O(32)$，额外空间复杂度为 $O(1)$。

### 示例代码

```c
#include <stdio.h>
int main()
{
    int T;
    scanf("%d", &T);
    while (T--)
    {
        int x;
        scanf("%d", &x);
        unsigned int bits = (unsigned int)x;

        for (int i = 31; i >= 0; i--)
        {
            printf("%u", (bits >> i) & 1U);
        }
        printf("\n");
    }
    return 0;
}
```

### 答案

### 题目分析

要注意的点有如下：

1. 注意 GPA 在 $59$ 和 $60$ 这里是一个跳跃间断点。GPA 小于等于 $59$ 分就是 $0$ 绩点，否则最少也是 $1.00$ 的绩点。

1. 计算综合成绩时，要么写成 $0.2 \times x_1 + 0.1 \times x_2 + \cdots$ 这种形式，要么如果要写 $\frac{x_1}{5} + \cdots$ 这种形式的话，要注意必须写成类似于 x1/5.0 这样。因为 $x_1$ 是整数， $5$ 也是整数，因此 x1/5 是整除，不保留小数点的。我相信你也不希望教务写程序时帮你所有项目都下取整了。

1. 最终综合成绩需要上取整为整数。在 C 语言里比较方便的是朝零取整，即 (int)x 这样。什么叫朝零取整呢？就是 $0$ 在哪里就向哪里取整，对于正数就是向下取整，对于负数就是向上取整。朝零取整有成截断取整，效果相当于直接舍弃小数点。那怎么实现向上取整呢？简单，如果 $x$ 有小数部分，那么朝零取整后肯定小于原数（因为成绩肯定都是大于等于 $0$ 的），朝零取整后再加 $1$ 就是向上取整的结果。

### 示例代码

```c
#include <stdio.h>
int x1,x2,x3,x4,x;
double tmp,GPA;
int main(){
    scanf("%d%d%d%d",&x1,&x2,&x3,&x4);
    tmp=x1/5.0+x2/10.0+x3/10.0+3.0/5*x4;
    //注意，不能写成 x1/5,3/5*x4，因此这样是整数之间的除法，是整除
    x=(int)tmp;//取 tmp 的整数部分
    if (tmp>x) x=x+1;//向上取整
    if (x<60) printf("0.00");
    else{
        GPA=4-3.0*((100-x)*(100-x))/1600.0;
        printf("%.2lf",GPA);
    }
    return 0;
}
```

## D 宇宙冷漠

### 题目

宇宙冷漠你们知道吗

#### 题目描述

Gsgmr 正在游玩《杀戮尖塔 II》的 储君。在本题设定的战斗中，Gsgmr 一共进行 n 个回合，第 i 个回合会依次打出 ai 张牌，其中第 j 张牌的基础伤害为 bi,j。基础伤害为 0 的牌被称为宇宙冷漠。每张牌按照以下规则结算伤害： · 如果这张牌的基础伤害大于 0，则造成等于其基础伤害的伤害。 · 如果这张牌是宇宙冷漠，则造成一次与上一张非宇宙冷漠牌相同的伤害。特别地，如果不存在上一张非宇宙冷漠牌，那么造成伤害为 0。在本题中，各回合之间相互独立，上一回合的牌不会影响下一回合。请你帮助 Gsgmr 计算每个回合造成的总伤害。

#### 输入格式

第一行包含一个整数 n ($1 \le n \le 2 \times 10^5$)，表示回合数。
接下来依次给出每个回合的信息。对于第 i 个回合：
· 第一行包含一个整数 $a_i$ ($1 \le a_i \le 2 \times 10^5$)，表示本回合打出的牌数。
· 第二行包含 ai 个整数 bi,1,bi,2,…,bi,a_i ($0 \le b_{i,j} \le 10^9$)，依次表示这些牌的基础伤害。保证 $\sum_{i=1}^{n} a_i \le 2 \times 10^5$。

#### 输出格式

输出 n 行，第 i 行包含一个整数，表示第 i 个回合造成的总伤害。

#### 样例输入

```text
5
3 3 2 5 5
0 0 3 0 2
5 128 203 0 176
89 3 114514 0 0
3 1000000000 0 0
```

#### 样例输出

```text
10
8
799
343542
3000000000
```

#### 样例解释

· 第一个回合，各张牌实际造成的伤害为 3,2,5，总伤害为 10。
· 第二个回合，各张牌实际造成的伤害为 0,0,3,3,2，总伤害为 8。

- 第三个回合，第三张牌是宇宙冷漠，重复第二张牌的 203 点伤害。各张牌实际造成的伤害为 128,203,203,176,89，总伤害为 799。
- 第四个回合，各张牌实际造成的伤害均为 114514，总伤害为 343542。
- 第五个回合，各张牌实际造成的伤害均为 $10^9$，总伤害为 $3 \times 10^9$。

Author: Gsgmr vs. ExplodingKonjac

### 答案

### 题目分析

对每个回合按照出牌顺序直接模拟。用 last 记录本回合最近一张非宇宙冷漠牌的伤害，用 sum 记录本回合的总伤害。

读入一张基础伤害为 $x$ 的牌时：

- 如果 $x > 0$，这张牌造成 $x$ 点伤害，并且它成为新的“上一张非宇宙冷漠牌”，所以令 last = x 。

- 如果 $x = 0$，这张牌的实际伤害等于 last ，且不能更新 last 。

一个回合开始时，把 last 设为 $0$。这样，如果开头连续出现若干张宇宙冷漠，它们都会正确造成 $0$ 点伤害。每个回合之间相互独立，所以每进入新回合时都必须重新将 last 和 sum 置为 $0$。

单张牌的伤害最大为 $10^9$，牌的总数最多为 $2 \times 10^5$，总伤害可能达到 $2 \times 10^{14}$，超过 int 范围。因此 last 、 x 和 sum 都使用 long long ，读写格式为 %lld 。

代码不需要保存所有牌，每读入一张就可以立即处理。设所有回合共有 $S$ 张牌，总时间复杂度为 $O(S)$，额外空间复杂度为 $O(1)$。

### 示例代码

```c
#include <stdio.h>
int main()
{
    int n;
    scanf("%d", &n);
    while (n--)
    {
        int a;
        scanf("%d", &a);

        long long last = 0;
        long long sum = 0;
        for (int i = 0; i < a; i++)
        {
            long long x;
            scanf("%lld", &x);
            if (x > 0)
            {
                last = x;
            }
            sum += last;
        }
        printf("%lld\n", sum);
    }
    return 0;
}
```

### 答案

### 题目分析

每个二进制位独立表示一个位置。只要 $a$ 或 $b$ 的对应位中至少有一个 $1$，合并后该位就为 $1$，所以合并状态为 a | b 。两者对应位都为 $1$ 时，合并后仍为 $1$，不会抵消，也不会产生进位。

在屏蔽状态 $c$ 中，位值为 $1$ 的位置必须关闭。对 $c$ 按位取反后，这些位置变成 $0$，其余位置变成 $1$，再与合并状态按位与，即可得到 y = (a | b) & ~c 。逐位看，结果为 $1$ 当且仅当原来的 $c$ 对应位为 $0$，并且 $a, b$ 对应位中至少有一个 $1$，恰好符合题目定义。

依次检查 $y$ 的第 $0$ 至第 $31$ 位。表达式 (y >> i) & 1U 将第 $i$ 位移到最低位，并清除其他位，结果为 $0$ 或 $1$。把这 $32$ 个结果相加，就得到 $1$ 的个数。循环必须包含第 $31$ 位，且每组数据开始时都要把计数器重新置为 $0$。逐位读取不会改变 $y$，可以直接输出原结果。

状态值的最大值为 $2^{32} - 1 = 4294967295$，超过 $32$ 位有符号 int 的上限，但可以直接使用 long long 保存 $a, b, c, y$，并用 %lld 读入和输出。此时仍然使用 y = (a | b) & ~c ： a | b 的第 $32$ 位及以上均为 $0$，按位与后这些位仍为 $0$，所以最终结果非负且不超过 $2^{32} - 1$，无需额外截断。随后用 (y >> i) & 1LL 检查低 $32$ 位即可。

本题并不要求必须使用无符号类型。下面的示例代码选择评测环境中的 $32$ 位 unsigned int ，对应输入输出格式为 %u ；改用 long long 和 %lld 同样正确。计数最大为 $32$，使用 int 和 %d 即可。无论选择哪种类型，都要扫描第 $0$ 至第 $31$ 位，并使输入输出格式与变量类型一致。

每组数据只扫描 $32$ 位，时间复杂度为 $O(32)$；共 $T$ 组数据，总时间复杂度为 $O(32T)$。各组可以读入后立即处理并输出，无需数组，额外空间复杂度为 $O(1)$。

### 示例代码

```c
#include <stdio.h>
int main() {
    int T;
    scanf("%d", &T);
    while (T--) {
        unsigned int a, b, c;
        scanf("%u%u%u", &a, &b, &c);
        unsigned int y = (a | b) & ~c;
        int cnt = 0;
        for (int i = 0; i < 32; i++) {
            cnt += (y >> i) & 1U;
        }
        printf("%u %d\n", y, cnt);
    }
    return 0;
}
```

### 答案

### 题目分析

用两个长度为 $26$ 的字符数组分别保存加密表和解密表。设 encrypt[i] 表示字母 'a' + i 加密后的小写字母。读入加密表时，用 %c 依次读入 $26$ 个字母：

```c
scanf(" %c", &encrypt[i]);
```

%c 前的空格会跳过前面的换行符等空白字符，不会把上一行结尾读入加密表。

读入一个映射 encrypt[i] 后，就可以同时建立反向的解密表：

```c
decrypt[encrypt[i] - 'a'] = 'a' + i;
```

这表示如果某个小写字母加密后变成 encrypt[i] ，那么解密 encrypt[i] 时就应该得到原字母 'a' + i 。由于加密表中的 $26$ 个字母互不重复，这张反向表一定能被完整填好。

读完 op 后，输入位置还在第二行的末尾，所以先用 %c 读到该行的换行符。之后再用 %c 逐个读入第三行的字符。这里的 %c 前不能加空格，否则正文开头、结尾和中间的空格都可能被跳过。

对正文中的每个字符 c ：

- 若它是小写字母，以 c - 'a' 作为下标，从对应的表中取出结果。

- 若它是大写字母，以 c - 'A' 作为下标，先查出对应的小写结果，再减去 'a' 、加上 'A' 恢复大写。

- 否则不做任何改变，原样输出。

### 示例代码

```c
#include <stdio.h>
int main()
{
    char encrypt[26], decrypt[26];
    for (int i = 0; i < 26; i++)
    {
        scanf(" %c", &encrypt[i]);
        decrypt[encrypt[i] - 'a'] = 'a' + i;
    }
    int op;
    scanf("%d", &op);
    char c;
    while (scanf("%c", &c) != EOF && c != '\n')
    {
        // 读掉 op 所在行剩余的字符
    }
    while (scanf("%c", &c) != EOF && c != '\n' && c != '\r')
    {
        if ('a' <= c && c <= 'z')
        {
            if (op == 0)
                c = encrypt[c - 'a'];
            else
                c = decrypt[c - 'a'];
        }
        else if ('A' <= c && c <= 'Z')
        {
            if (op == 0)
                c = encrypt[c - 'A'] - 'a' + 'A';
            else
                c = decrypt[c - 'A'] - 'a' + 'A';
        }
        printf("%c", c);
    }
    printf("\n");
    return 0;
}
```

## G 位运算方程

| 难度 | 考点 |
| --- | --- |
| 4 | 位运算、分类讨论、无符号整数 |

### 题目

#### 题目描述

kanade 在学习了位运算后突发奇想：既然我们能解含有加减乘除的方程，那么能不能解一个含有位运算的方程呢？于是她写下了三种方程： 1. a ^ x = b2. a | x = b3. a & x = b 其中 ^ 表示按位异或，| 表示按位或，& 表示按位与。对于两个给定的非负整数 a 和 b，kanade 发现有时可以找到一个非负整数 x，使得某些方程成立，但有时不能。 kanade 想知道，对于每组 a 和 b，满足对应方程的最小非负整数 x 是多少；如果不存在这样的 x，输出 -1 。请你写一个程序帮帮她！

#### 输入格式

第一行一个正整数 n (1 ≤ n ≤ 104) ，表示数据组数。
接下来 n 行，每行三个整数 op, a, b ，用空格分隔。
op 表示方程类型：
· op=1：a ^ x = b
· op=2：a | x = b
· op=3：a & x = b
a, b 为两个 unsigned int 范围的整数，即 0 ≤ a, b ≤ 232 - 1。

#### 输出格式

输出 n 行，每行一个整数。对于每组数据：

- 若存在满足方程的最小非负整数 x ，则输出这个 x 。
- 若不存在则输出 -1 。

#### 输入样例

```text
6
1 5 3
2 5 7
3 5 4
2 1 2
3 2 3
1 0 4294967295
```

#### 输出样例

```text
6
2
4
-1
-1
4294967295
```

#### 样例解释

为了方便，在样例中，我们用 4 位二进制数表示，从左到右依次标为第1位、第2位、第3位、第4位。

- 1 5 3：5 是 0101，3 是 0011。0101 与未知数异或得到 0011，未知数需要在第2、3位填1，得到 0110，也就是6。
- 2 5 7：5 是 0101，7 是 0111。0101 已满足2、4位，为了满足第3位，未知数只填第3位为1，得到 0010，也就是2。
- 3 5 4：5 是 0101，4 是 0100。目标第2位是1，5 的第2位已经是1，未知数只保留第2位，得到 01 00，也就是4。
- 2 1 2：1 是 0001，2 是 0010。1 的第4位是1，结果第4位必定是1。但 2 的第4位是0，矛盾，无解。输出 -1。
- 3 2 3：2 是 0010，3 是 0011。2 的第4位是0，结果第4位必定是0。但 3 的第4位是1，矛盾，无解。输出 -1。
- 1 0 4294967295：这个样例是为了提醒你输入的数可能大于 int 的最大值，如果你用 %d 输出，这个数会被错误地打印成 -1，请务必使用 %u 输出。

#### 提示

· 数据范围：在常见编译器中：
· int 的范围是 $-2^{31}$ 到 $2^{31}-1$。
· unsigned int 的范围是 0 到 $2^{32}-1$。

- 输入输出格式：注意到 a, b 的范围超过了 int ，所以请使用 unsigned int 存储 a, b ，使用 s canf("%u%u", &a, &b) 读取无符号整数，使用 printf("%u", ans) 输出有解时的答案。
- 独立考虑每一位：位运算对于二进制中的每一位是互相独立的。可以先考虑只有一位的情况，再推广到 32 位。这是解决所有位运算方程的核心思路。

### 答案

### 题目分析

由于这些数的每一位互相独立，因此我们可以单独考虑二进制中的某一位。考虑固定的一位，在该位上

- 数字 a 的值为 A

- 数字 b 的值为 B

- 数字 x 的值为 X

其中， $A$、 $B$、 $X \in \{0, 1\}$。

#### 1. 异或

由于 $A \oplus A = 0$ 且 $0 \oplus X = X$，我们可以对两边同时异或上 $A$：

$$
\begin{aligned}
A \oplus X &= B \\
A \oplus A \oplus X &= A \oplus B \\
X &= A \oplus B
\end{aligned}
$$

所以方程有且仅有唯一的解： $x = a \oplus b$

#### 2. 按位或

分情况：

- 无解情况： A =1 , B = 0 ， X 取任何值方程都不成立。这种情况等价于 A & ~B == 1 。

- 有解情况： B = 1 ，只需 A | X == 1 。为了让 x 最小，如果 A 已经是 1 ，则 X 取 0 ；否则 X 取 1 。这种情况只需 X = B & ~A ，也就是只保留 b 中为 1 且 a 中为 0 的位。

因此：

- 无解条件： (a & ~b) != 0 ，或写作 (a | b) != b

- 有解时： x = b & ~a

#### 3. 按位与

分情况：

- 无解情况： A = 0 , B = 1 ， X 取任何值方程都不成立。这种情况等价于 B & ~A == 1 。

- 有解情况：如果 B = 0 ，为了让 x 最小，那么 X 取 0 ；如果 A = 1 , B = 1 ，那么 X 只能取 1 。这种情况只需 X = B 。

因此：

- 无解条件： (b & ~a) != 0 ，或写作 (a & b) != b

- 有解时： x = b

### 示例代码

```c
#include <stdio.h>
int main() {
    int n;
    scanf("%d", &n);
    while (n--) {
        int op;
        unsigned int a, b;
        scanf("%d%u%u", &op, &a, &b);
        if (op == 1) {
            printf("%u\n", a ^ b);
        } else if (op == 2) {
            if ((a | b) != b) {
                printf("-1\n");
            } else {
                printf("%u\n", b & ~a);
            }
        } else if (op == 3) {
            if ((a & b) != b) {
                printf("-1\n");
            } else {
                printf("%u\n", b);
            }
        }
    }
    return 0;
}
```

## H 下一个同亮度编号

### 题目

#### 题目背景

阿笠博士 和 muzermat 一起做了一个灯光编号盒，打算给少年侦探团的寻宝游戏使用。面板从左到右显示一个固定长度的二进制编号，所有灯的亮度相同，亮灯为 1，熄灯为 0。为了让相邻两次提示看起来一样亮，编号盒每次都要保持亮灯总数不变，同时把编号增大到符合要求的最小值。到了没有后继编号的时候，就结束这一轮游戏。看着 muzermat 兴致冲冲递过来的玩具，灰原哀 在一旁翻了个白眼，显然是觉得这个东西十分幼稚。「这个东西怎么玩？」不过， 柯南 倒是很快发现，直接把编号加一常常会改变亮灯数。请帮他算出每个当前编号之后，盒子应当显示的编号。

#### 输出

#### 输入样例 2

#### 样例解释

### 答案

### 题目分析

两种解法都利用同一个构造原则：找到最低的可行位置，将该位从 $0$ 改为 $1$，更高位保持不变，再将低位剩余的 $1$ 尽量放到最低端。

#### 解法一：逐位扫描并构造

比较两个不同的二进制整数时，由最高的不同位决定大小。若 $y > x$，在这个最高不同位 $i$ 上，原数必须为 $0$，新数必须为 $1$；比它更高的位保持不变。

设原数在第 $i$ 位以下共有 $c$ 个 $1$。把第 $i$ 位从 $0$ 改成 $1$ 后，为保持总亮灯数不变，低 $i$ 位只能再放 $c - 1$ 个 $1$。因此这一位置可作为变化位，当且仅当它原本是 $0$，且低位已经出现至少一个 $1$。

应从低位到高位寻找第一个可行位置。若选择更高的位置作为最高不同位，所得数一定更大：在那个更高的位置，较低变化位的方案仍保留原来的 $0$，而较高变化位的方案将它置为 $1$。因此第一个可行位置给出了最优的最高不同位。

位置确定后，为使结果最小，应把剩余的 $c - 1$ 个 $1$ 放在最低的 $c - 1$ 位，其他低位清零。这部分的数值为 $2^{c-1} - 1$。保留第 $i$ 位以上的原值、设置第 $i$ 位、填入最小低位，即可构造答案。

代码扫描时用 ones 统计已经经过的低位中 $1$ 的数量。若在既定的 $w$ 位内找不到可行位置，则无解，包括 $x = 0$、全为 $1$，以及所有 $1$ 已集中在最高若干位的情况。不能扩展位宽，也不能把 $x$ 本身当成答案。

状态使用 unsigned long long ，读写使用 %llu ，位权常量写为 1ULL 。最大保留高位的移位量为 $60$，构造出的数始终小于 $2^w \le 2^{60}$； ones - 1 仅在 ones > 0 时使用，所有移位量都小于 $64$。每组时间复杂度为 $O(w)$，额外空间复杂度为 $O(1)$；共 $T$ 组时，总时间复杂度为 $O(Tw_{\max})$，其中 $w_{\max} \le 60$。

#### 解法二：用位运算直接完成构造

当 $x > 0$ 时，设其二进制末尾有 $t$ 个 $0$，再向左是一段连续的 $r$ 个 $1$，其中 $r \ge 1$，这一段左侧的下一位是 $0$。必要时可以暂时在原位宽左侧补一个 $0$，构造完成后再判断是否超出位宽。原数的局部形态为

$$
\text{高位前缀}\ 0\ \underbrace{11\cdots 1}_{r\ \text{个}}\ \underbrace{00\cdots 0}_{t\ \text{个}}。
$$

按补码性质， low = x & -x 只保留 $x$ 最低的一个 $1$，所以 $low = 2^t$。这是因为对 $x$ 按位取反再加一后，末尾的 $t$ 个 $0$ 仍为 $0$，第 $t$ 位仍为 $1$，比它更高的位与原数相反；两者按位与后，仅剩第 $t$ 位。

计算 next = x + low ，加法会从最低的 $1$ 开始连续进位，将这 $r$ 个 $1$ 清零，并把它们左侧的 $0$ 置为 $1$，更高位保持不变。这恰好完成了解法一中寻找最低可行变化位并进位的步骤。

接下来还需要把 $r - 1$ 个 $1$ 放到最低端。 x & ~next 恰好取出进位时被清掉的那段 $1$，其数值为 $(2^r - 1)2^t$；除以 low 后得到 $2^r - 1$，再右移一位，得到 $2^{r-1} - 1$。这就是最低 $r - 1$ 位全为 $1$ 的数，与 next 按位或即可得到答案：

```c
long long low = x & -x;
long long next = x + low;
long long y = (((x & ~next) / low) >> 1) | next;
```

例如，取 $w = 6$、 $x = 28$，构造过程为：

```text
x            = 011100
low          = 000100
next         = 100000
x & ~next    = 011100
补回的低位 = 000011
y            = 100011
```

所得 $y = 35$，仍有三个 $1$，且是严格大于 $28$ 的最小合法编号。由于该方法与解法一选择相同的变化位，并将相同数量的 $1$ 放在最低端，其正确性和最小性由前述构造证明保证。

当 $x = 0$ 时没有最低的 $1$，也不存在亮位数相同的更大整数，应直接输出 -1 ，同时避免除以零。对于 $x > 0$，若所得 $y \ge 2^w$，说明最低可行的变化位已经超出允许位宽，因此无解；否则输出 $y$。这也覆盖了全为 $1$ 或所有 $1$ 已集中在最高若干位的情况。

本题有 $0 \le x < 2^{60}$，可以使用有符号 long long 。 -x 可表示， low 为正数， next 不超过 $2^{60}$，补回低位后的结果小于 $2^{61}$，都不会发生有符号溢出；参与右移的商非负。判断上界时使用 1LL << w ，其中 $w \le 60$，不能写成 1 << w 。在固定的 64 位整数模型下，每组只需常数次运算，时间复杂度为 $O(1)$，额外空间复杂度为 $O(1)$；共 $T$ 组时总时间复杂度为 $O(T)$。

### 示例代码

解法一：逐位扫描并构造

```c
#include <stdio.h>
int main() {
    int T;
    scanf("%d", &T);
    while (T--) {
        int w;
        unsigned long long x;
        scanf("%d%llu", &w, &x);
        int ones = 0, found = 0;
        unsigned long long y = 0;
        for (int i = 0; i < w; i++) {
            if ((x >> i) & 1ULL) {
                ones++;
            } else if (ones > 0) {
                unsigned long long high = (x >> (i + 1)) << (i + 1);
                y = high | (1ULL << i) | ((1ULL << (ones - 1)) - 1ULL);
                found = 1;
                break;
            }
        }
        if (found) {
            printf("%llu\n", y);
        } else {
            puts("-1");
        }
    }
    return 0;
}
```

解法二：位运算直接构造

```c
#include <stdio.h>
int main() {
    int T;

        int w;
        long long x;
        scanf("%d%lld", &w, &x);
        if (x == 0) {
            puts("-1");
        } else {
            long long low = x & -x;
            long long next = x + low;
            long long y = (((x & ~next) / low) >> 1) | next;
```

### 答案

### 题目分析

张量的形状会改变，但底层数据的一维顺序始终不变。因此，只需维护：

- 一个长度为 $N$ 的一维数组 data ；

- 当前维度数 $c$；

- 当前各维长度 $D_1, D_2, \ldots, D_c$。

对于一个合法坐标 $(x_1, x_2, \ldots, x_c)$，可以用循环计算其一维下标：

```text
index = 0
依次处理 i = 1, 2, ..., c：
    index = index * D_i + x_i
```

最终得到

$$
index = (((x_1 D_2 + x_2)D_3 + x_3)\cdots)D_c + x_c。
$$

由于只有在坐标合法时才继续计算，始终有 $0 \le index < N \le 10^6$，不会发生溢出。

#### 查询与修改

先判断输入的维度数是否等于当前维度数。若不相等，直接判为非法；否则依次检查每个坐标是否满足 $0 \le x_i < D_i$。

若操作合法，则计算一维下标。查询操作输出 data[index] ，修改操作给 data[index] 赋新值且不输出。非法操作统一输出 -1 。

即使维度不匹配，也必须先读完该操作行中给出的全部 $c$ 个坐标；否则会影响后续输入的读取。

#### 重塑

重塑合法当且仅当新形状的各维长度之积等于固定的元素总数 $N$。合法时只替换当前维度数和形状，不修改 data 。

直接连乘可能溢出。由于每个新维度长度都为正数，在执行 product *= D'_i 前检查：

```text
product > N / D'_i
```

若条件成立，则乘积必然大于 $N$，当前操作一定非法，不要再连乘导致溢出反而变“合法”了。

判断重塑操作是否合法时可能发生乘法溢出。在每次乘法前，算法检查当前乘积是否大于 $N / D'_i$。若成立，新乘积必然大于 $N$，不可能等于 $N$，因此判为非法。否则新乘积不超过 $N$，乘法安全。全部处理后，乘积等于 $N$ 当且仅当重塑合法。证毕。

### 示例代码

```c
    n = 1;

    for (int i = 0; i < n; i++)
        scanf("%d", &a[i]);

    {
        int op, c;
        scanf("%d%d", &op, &c);

        {

                    ok = 0;
            }
            printf("%d\n", ok ? a[pos] : -1);
        }
        if (op == 2)
        {
            int pos = 0, val = 0, ok = k == c;
            for (int i = 0, x; i < c; i++)
            {
                scanf("%d", &x);
                pos = pos * d[i] + x;
                if (x < 0 || x >= d[i])
                    ok = 0;
            }
            scanf("%d", &val);

                a[pos] = val;
            else
                printf("-1\n");
        }
        if(op == 3)

            {

            }
        }
    }
    return 0;
}
```

### 样例1：

a1 和 a2 同时异或 4 ，变为 6 7 4 5 6 6 a2 和 a3 同时异或 1 ，变为 6 6 5 5 6 6 a3 和 a4 同时异或 3 ，变为 6 6 6 6 6 6 4 + 1 + 3 = 8 ###样例2：能量球的能量值全部相同，故不需要花费额外的能量 ###样例3：这两个能量球无论异或什么数都没办法变得相等，无解，故输出 -1

### 答案

### 题目分析

异或运算每一位是独立的。操作量 $x$ 可以写成

$$
x = \sum_{i \ge 0} 2^i [x\ \text{的第}\ i\ \text{位是}\ 1].
$$

也就是说，第 $i$ 位每做一次操作，就会给总花费贡献 $2^i$。设第 $i$ 位最少需要操作 $w_i$ 次，总答案就是

$$
res = \sum_{i=0}^{30} 2^i w_i.
$$

因此只需要对每一位单独求出 $w_i$，再乘 $2^i$ 累加。

固定看某一位，所有数都变成 $0/1$。一次操作只有三种本质效果：

- 00 -> 11 ：产生两个相邻的 1 ；

- 11 -> 00 ：消掉两个相邻的 1 ；

- 01 -> 10 、 10 -> 01 ：交换相邻的 0 和 1 ，也就是让一个 1 向旁边移动一格。

因此对某一位，就是在一个环上交换不同元素和取反相同元素。最终有两种选择：全部变成 0 ，或全部变成 1 。

先看全部变成 0 ：要把所有的 1 都消掉，必须两两配对。设这些 1 的位置按环上顺序为 $p_1 < p_2 < \cdots < p_k$。每消掉一对 1 ，就是把它们通过交换移到相邻位置，再执行一次 11 -> 00 。若两个 1 在环上的距离是 $d$，那么把它们配对消掉的代价就是 $d$。对于位置 $u < v$ 的两个 1 ，不绕回时距离是 $v - u$，绕回时距离是 $u + n - v$。因此我们希望让这些 1 两两配对，使总距离最小。

设有 $k$ 个 1 ：

若 $k = 0$，已经全是 0 ，代价为 $0$。

若 $k$ 是奇数，则无论如何都会剩下一个 1 ，不能全部变成 0 ；这时只能尝试全部变成 1 。

当 $k$ 是偶数时，最优配对一定是按环上顺序相邻配对。因为如果两个配对的区间交叉或嵌套，把它们改成相邻配对不会更差。于是只有两种可能：

**1. 顺序配对** $(p_1, p_2), (p_3, p_4), \ldots, (p_{k-1}, p_k)$，代价为

$$
c_1 = \sum_{j=1}^{k/2} (p_{2j} - p_{2j-1}).
$$

**2. 错开配对** $(p_2, p_3), (p_4, p_5), \ldots, (p_k, p_1)$，代价为

$$
c_2 = \left(\sum_{j=2}^{k/2} (p_{2j-1} - p_{2j-2})\right) + (p_1 + n - p_k).
$$

第二种是错开一位配对，其中最后一对 $(p_k, p_1)$ 要从 $p_k$ 绕一圈回到 $p_1$，距离是 $p_1 + n - p_k$。

全部变成 1 的做法完全相同，只要把原来的 0 看成要消掉的点，记录所有 0 的位置再配对即可。

若当前选择消掉值 $t$（ $t = 0$ 或 $1$），把对应位置记为 $p_1 < p_2 < \cdots < p_{k_t}$，并记两种代价为 $c_1(t), c_2(t)$，则

$$
w_i(t) = \begin{cases} \min(c_1(t), c_2(t)), & k_t\ \text{为偶数}, \\ +\infty, & k_t\ \text{为奇数}. \end{cases}
$$

因此第 $i$ 位的最少操作次数为

$$
w_i = \min(w_i(0), w_i(1)).
$$

第 $i$ 位对总答案的贡献是 $2^i w_i$，最终答案为

$$
res = \sum_{i=0}^{30} 2^i w_i.
$$

代码中 $t = 0, 1$ 分别表示“把当前位为 $t$ 的位置消掉”：消掉 0 就是最终全变成 1 ，消掉 1 就是最终全变成 0 。两种选择都可行时取较小值；如果某一位两种都不可行，就输出 -1 。

时间复杂度为 $O(31n)$，空间复杂度为 $O(n)$。

### 示例代码

```c
#include <stdio.h>
int n, a[100010], b[100010];
int pos[2][100010];
long long res;
int main() {
    scanf("%d", &n);
    for (int i = 1; i <= n; i++) scanf("%d", &a[i]);
    int flag = 0;
    for (int i = 0; i <= 30; i++) {
        int cnt[2] = {0, 0}, ans = 1000000000, tot;
        for (int j = 1; j <= n; j++) {
            b[j] = ((a[j] >> i) & 1);
            pos[b[j]][++cnt[b[j]]] = j;
        }

        for (int t = 0; t < 2; t++) {
            int k = cnt[t];
            if (k & 1) continue;
            if (k == 0) tot = 0;
            else {
                int c1 = 0, c2 = 0;

                //(1,2),(3,4)...配对
                for (int j = 1; j <= k / 2; j++) c1 += pos[t][2 * j] - pos[t][2 * j - 1];

                //(2,3),(4,5)...,(k,1)回绕配对
                for (int j = 2; j <= k / 2; j++) c2 += pos[t][2 * j - 1] - pos[t][2 * j - 2];
                c2 += pos[t][1] + n - pos[t][k];

                tot = c1 < c2 ? c1 : c2;
            }
            if (ans > tot) ans = tot;
        }

        if (ans == 1000000000) {
            flag = 1;
            break;
        }
        res += ((1ll * ans) << (1ll * i));
    }
    if (flag) puts("-1");
    else printf("%lld", res);
}
```
